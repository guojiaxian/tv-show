# 数智中心大屏聚合平台（TV Show Center）

面向小米电视（Android TV / MIUI TV）等安卓大屏设备的**大屏展示聚合应用**：首页以卡片宫格聚合多个大屏入口，点击后通过 WebView 加载指定的 Web 大屏页面，并把电视遥控器按键完整映射到页面内元素（焦点移动 / 触发点击）。

采用 **C/S 架构**，职责边界清晰：

- **服务端（内容）**：页面列表、系统标题是唯一数据源，日常增删改内容**无需重新安装 APK**；
- **客户端（展示策略）**：**是否轮询、轮询哪些页面与间隔、2×2 分区各放什么**都是本机设置，各台电视互不影响；
- **多设备互控（1.8 新增）**：**独立控制台 `/console`**（平板存书签即用，自身不受控）对全场设备（电脑 / 平板 / 电视）单台 / 群组 / 一键场景地下发「显示某页 / 轮询 / 2×2 分屏 / 回首页 / 刷新」；电脑 / 平板显示端被控时**只切画面、不锁鼠标**；电视端锁定遥控按键并以【菜单】首项开关交还（退出需二次确认），见第九节。

遥控器交互（本版按现场反馈调整，进入即配置）：

| 操作 | 结果 |
| --- | --- |
| 首页按【菜单】→「轮询展示」 | **直接进入轮询播放**，无需先做任何设置（首次进入默认轮询全部页面） |
| 轮询播放页再按【菜单】 | 弹出控制菜单，其中「轮询设置」可打开设置界面（开关 / 间隔 / 页面与顺序） |
| 首页按【菜单】→「分区展示（2×2 拼接）」 | **直接进入 2×2 拼接页**，方向键选格、按【确定】为该格选页面 |

- 应用包名：`com.digitalcenter.tvshow`
- 客户端版本：`1.8`（versionCode 17）· **多设备互控**：独立控制台 `/console`（单文件页，平板书签直达，自身不注册受控）对全场设备下发显示 / 轮询 / 分屏 / 场景；电脑 / 平板显示端被控只切画面不锁鼠标；电视端锁定遥控 + 【菜单】首项模式开关（退出二次确认）；场景预设（一键切换）与同相轮询（默认关）· 1.7 的旧内核修补与 1920×1080 强制视口全部保留
- 服务端：Node.js 内置模块（`server/server.js`），默认端口 `18080`；唯一 npm 依赖 `esbuild` 仅用于「旧内核兼容转译」，可不装；控制通道 `server/ctl.js` 同为零依赖
- 最低系统：Android 6.0（API 23），目标 API 34，横屏全屏

### 安装到小米电视

1. 电视端开启「设置 → 账号与安全 → 未知来源应用安装」，并打开「ADB 调试」。
2. 任选一种方式安装：
   - **U 盘**：把 APK 拷入 U 盘 → 插入电视 → 用电视上的文件管理器点击安装；
   - **adb**：`adb connect <电视IP>:5555` 然后 `adb install -r dist/TvShowCenter-v1.7-release.apk`。
3. 安装后可在「应用」列表找到「大屏聚合平台」。若出现在 Android TV 风格桌面上，会显示 TV Banner。

## 二、服务端管理系统与页面配置

日常所有内容维护都在服务端完成，**改完不用碰电视**。

### 启动服务端

```bash
node server/server.js                    # 默认端口 18080
node server/server.js --port 9000        # 指定端口
PORT=9000 node server/server.js          # 或用环境变量
node server/server.js --host 127.0.0.1   # 只监听本机（配合反向代理更安全）
```

启动后：

| 地址 | 用途 |
| --- | --- |
| `http://<服务器IP>:18080/` | **电脑浏览器客户端（站点首页）**，别名 `/app`、`/client` |
| `http://<服务器IP>:18080/console` | **设备控制**（客户端「设备控制」screen 的直达别名，平板可存书签） |
| `http://<服务器IP>:18080/setting` | **管理（设置）页面**，别名 `/admin` |
| `http://<服务器IP>:18080/preview` | **电视端 1:1 预览页**，别名 `/preview.html` |
| `http://<服务器IP>:18080/api/config` | 客户端拉取接口 |

> 三个页面与所有接口**共用 18080 一个端口**，服务端不会启用第二个端口。首页顶栏的「更多 ▾」二级菜单内置了**「电视端预览」→ `/preview`** 与 **「设置」→ `/setting`** 两个跳转入口。
>
> **升级注意**：页面文件（客户端 / 管理页 / 控制台 / 预览页）是每次请求都读盘的，替换文件即生效；但 **`server.js` 及其模块（`ctl.js` 等）的变更必须重启服务端进程**才能生效——例如 1.8 新增的 `/console` 路由与 `/api/ctl/*` 接口，只替换页面文件不重启会得到 `{"error":"未找到接口 GET /console"}`。重启不影响数据（`config.json` / `devices.json` 均在磁盘）。

通常无需 `npm install`：服务端只用到 Node 内置模块，把 `server/` 目录拷到任意装了 Node 的机器即可运行（内网离线环境同样适用）。**唯一例外**是「旧内核兼容转译」：需要联网执行一次 `npm install` 安装 `esbuild`；不装也能正常启动，只是该功能不生效（自动退回原样透传）。

### 管理后台能做什么

| 功能 | 说明 |
| --- | --- |
| **系统标题修改** | 主标题、副标题、退出提示文案、是否弹退出确认；保存即写入服务端 |
| **新增页面** | 标题、描述、URL、图标、主题色、缩放、自动登录账号密码与选择器、强制原址打开、history 路由 SPA、旧内核兼容转译（含 `compatTarget`） |
| **编辑 / 删除页面** | 表格行内操作，删除后电视端不再显示该入口 |
| **排序** | 上移 / 下移，对应电视端首页宫格的排列顺序 |
| **状态栏** | 当前 `version` / `epoch` / 页面数 / 更新时间 |
| **强制客户端全量刷新** | 担心某台设备数据不一致时，让所有客户端下次同步重拉全量 |

> 轮询与分区**不在管理后台**：它们是每台电视自己的展示策略，见第三、四节。

### 电视端如何生效

内容改动后，电视端在以下时机自动应用（**无需重装应用**）：

1. **应用启动时** —— 自动比对版本，有变更即增量更新；
2. **回到前台时** —— 距上次同步超过 15 秒则同步一次；
3. **按遥控器【菜单】键 →「立即同步配置」** —— 手动同步，底栏会提示结果。

底栏右侧会常显同步状态：`已同步 vN` / `同步中…` / `离线（使用缓存）`。

### 客户端服务器地址

按交付约定地址**打包内置**在 `app/src/main/assets/config.json` 的 `serverBaseUrl`：

```json
{
  "serverBaseUrl": "http://10.8.11.4:18080",
  "sync": { "connectTimeoutMs": 3000, "readTimeoutMs": 5000, "pollIntervalSec": 0, "minSyncIntervalMs": 15000 },
  "fallback": { "appTitle": "...", "entries": [ ... ] }
}
```

- 部署到你们内网时，把 `serverBaseUrl` 改成实际服务器地址后重新出包即可（改这一行）。
- 现场需要**临时切换服务器**又不想重装时，可把同名文件放到
  `/sdcard/Android/data/com.digitalcenter.tvshow/files/config.json`（优先级高于包内，`adb push` 即可），无需重新出包。
- `fallback` 是**兜底内容**：首次安装、服务器不可用、或配置还没同步下来时显示，保证电视端永远有内容。

管理接口（供后台页面调用，内网免鉴权）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/config` | 完整配置（含 version/epoch/rev） |
| PUT | `/api/admin/meta` | 修改系统标题等 |
| POST | `/api/admin/entries` | 新增页面 |
| PUT | `/api/admin/entries/:id` | 更新页面 |

| POST | `/api/admin/entries/reorder` | 按 `ids` 重排 |
| POST | `/api/admin/epoch/bump` | 强制客户端下次重拉全量 |
| GET | `/api/admin/health` | 健康检查 |

客户端接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/config?since=<version>&epoch=<epoch>` | 增量拉取：无变更为 `304`，否则返回全量或增量 |
| GET | `/api/config?full=1` | 强制全量 |
| GET | `/api/cameras` | 摄像头列表（编号、标题、在线状态），只下发展示参数，**不含 RTSP 地址与凭据** |
| GET | `/cam/<编号>.mjpg?q=high` | 摄像头实时画面（MJPEG 流）：`q=high` 主码流，缺省子码流 |

| GET | `/cam/logo.png` | 画面墙品牌格图片（客户端叠在黑底上显示），未配置时返回 `404` |
| GET | `/api/version` | 极轻量的版本探测 |

多设备互控 · 控制通道接口（`/api/ctl/*`，内网免鉴权，与 `/api/admin/*` 同一信任模型）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/ctl/beat` | 设备心跳（3s 一拍）：注册 / 上报状态 / 领指令 / 捎带模式开关意图 `switchTo` |
| POST | `/api/ctl/send` | 下发指令 `{targets, cmd, args}`；展示类（show/rotate/zone/home）自动接管，维护类（refresh/sync）不改模式；`targets:["*"]` = 全部设备 |
| POST | `/api/ctl/release` | 「取消控制」：目标设备 `managed=false` 并清空 desired（与设备端开关同一状态翻转） |
| GET | `/api/ctl/devices` | 设备列表（模式 / 在线判定 / reported 状态 / 待送达标记）+ 场景列表 |
| PUT / DELETE | `/api/ctl/device/:id` | 设备改名 / 开关 `bootRestore` / 从档案移除 |
| POST | `/api/ctl/scenes` | 保存场景：直接传 `steps`，或快照当前现场（受控设备取 desired，本地设备把上报状态转为等价指令） |
| POST | `/api/ctl/scenes/:id/apply` | 应用场景（逐台下发，seq 逐台自增；离线设备存储转发补投递） |
| PUT / DELETE | `/api/ctl/scenes/:id` | 场景重命名 / 删除 |

> 服务端接口只围绕**内容**（元信息 + 页面列表）。轮询与分区是客户端本机设置，服务端不提供对应接口。

### 页面字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 否 | 唯一标识，留空自动生成；创建后不建议修改（客户端按 ID 识别页面） |
| `title` | **是** | 卡片标题（电视端建议 ≤20 字） |
| `type` | 否 | `url`（默认，普通网页）或 `camera`（**内置摄像头画面墙**，客户端直接播放实时画面，无需填 `url`） |
| `subtitle` | 否 | 卡片描述 |
| `url` | **是** | 大屏地址，必须以 `http://` 或 `https://` 开头；`type=camera` 时忽略 |
| `accent` | 否 | 主题色 `#RRGGBB` |
| `icon` | 否 | `storage` / `env` / `security` / `default` |
| `scale` | 否 | 缩放：`0` 自动适配，或 `50`–`200` |
| `autoFit` | 否 | 内容超宽时自动缩小铺满，默认 `true` |
| `allowInsecureSsl` | 否 | 忽略自签名证书错误，默认 `false` |
| `openOriginal` | 否 | **强制原址打开**：点击卡片时在新标签页直接访问原地址（配了自动登录则走代理地址，由服务端注入自动登录脚本），不进内嵌壳；轮询展示自动跳过。默认 `false` |
| `spaHistory` | 否 | **history 路由 SPA**：代理打开报 SPA 自身 404（如 Uptime Kuma 的「未找到该页面」）时勾选，代理会在页面启动时剥离代理前缀，让 SPA 路由正确匹配。传统多页站点勿开。默认 `false` |
| `autoLogin` | 否 | 自动登录：`enabled` / `username` / `password` / 4 个可选选择器 |

## 三、轮询展示（客户端本机设置）

轮询是**每台电视自己的展示策略**：服务端只提供"有哪些页面可以展示"，由电视自己决定轮播哪些页面、间隔多久。因此一台电视改设置不会影响其它电视，服务端也不需要保存任何轮询状态。

### 怎么进入（两级菜单，进入即播放）

| 操作 | 结果 |
| --- | --- |
| 首页【菜单】→「轮询展示」 | **直接开始轮询播放**（这台电视还没选过轮询页面时，默认让全部页面参与，点开即用） |
| 轮询播放页再按【菜单】 | 弹出控制菜单，首项即「轮询设置」 |
| 轮询设置里按【返回】 | 回到轮询播放并按新设置立刻生效（不是回首页） |

### 轮询设置界面

| 项 | 说明 |
| --- | --- |
| 开机自动播放 | 开启后应用启动会直接进入轮询播放（**默认关闭**，遥控器随时可用【菜单】→「轮询展示」手动进入） |
| 每页停留时间 | 单位秒，**默认 15**，取值 1–3600；用遥控器从预设值（5/10/15/20/30/45/60/120/300）中选，无需软键盘 |
| 参与轮询的页面 | 列出服务端所有页面，按【确定】加入/移出；按【左/右】调整播放顺序 |

每次改动都会写入本机设置，并把计时起点重置为当前时刻（从第 1 页重新开始）。

### 电视端行为

- 从首页【菜单】→「轮询展示」或开机自动播放进入后，**按【返回】回到首页并停止轮询**。
- 右上角显示 `轮询 2/3 · 剩余 12 秒`；切页时旧页面保持显示，只显示顶部进度条，不闪白屏。
- 某一页加载失败不会中断轮播，到点继续切下一页；服务端把某个页面删掉后，轮询序列会自动跳过它。

### 计时方式

位置由**本机写入的时钟起点**推导：

```
index = floor((当前时间 - startedAt) / 间隔秒数) mod 序列长度
```

由于起点随设置保存写入本机，退出重进、进程被杀后重新打开都会**接着原来的进度**继续，而不是每次都从第 1 页重新计时；切页时机对齐到"间隔边界"（而不是"从现在起再等 N 秒"），长时间运行也不会累积漂移。

> 与 1.1.0 的差异：早期版本由服务端统一下发序列与时钟，多台电视会自动显示同一页；现在轮询归客户端后，**每台电视各自配置、各自计时**，这正是"分区/轮询由客户端决定"的要求。

> 与 1.2.0 的差异：轮询不再需要先进入独立的"开始轮询播放"入口。首页【菜单】→「轮询展示」**直接开始播放**（从未选过页面时默认全部页面参与），要改设置时在**轮询播放页再按一次【菜单】**→「轮询设置」。原「启用轮询」开关更名为「开机自动播放」，只决定应用启动时是否自动进入轮询，不再影响手动进入。

## 四、分区展示（拼接大屏 2×2）

四个分区各占屏幕四分之一，**每个分区按 1920×1080 的分区视口渲染**。

### 分辨率是怎么保证的

客户端为**每个分区单独创建一个 WebView，并按格子的物理宽度重写其密度**：

| 屏幕 | 每格物理像素 | 重写后的 density | 该分区的 CSS 视口 | 效果 |
| --- | --- | --- | --- | --- |
| 3840×2160 拼接屏 | 1920×1080 | 1.0 | 1920×1080 | **1:1 原生呈现**，无缩放 |
| 1920×1080 普通电视 | 960×540 | 0.5 | 1920×1080 | 页面仍按 1920×1080 布局，整体缩放 50% |

也就是说：**内容始终按 1920×1080 的分区视口渲染**，屏幕不够大时是等比缩小，而不是让页面按更小的视口去重新布局。想要 1:1 无损呈现需要 3840×2160 的拼接屏（4 块 1920×1080 拼接）。

### 配置方式（进入即配置，页内直接选）

**没有独立的"分区设置"界面**：首页按【菜单】→「分区展示（2×2 拼接）」直接进入 2×2 页面，在页面里用遥控器完成配置：

| 按键 | 行为 |
| --- | --- |
| 方向键 | 在 2×2 四格之间移动当前分区（边界不循环）；目标格青色描边**亮一下即淡出**，不做常驻边框 |
| 确定（OK） | 为当前高亮的格选页面：弹层列出服务端全部页面 + 「不使用」 |
| 菜单 | 控制菜单：刷新全部页面 / 返回首页 |
| 返回 | 返回首页 |

选择结果保存在本机，**与其它电视无关**；服务端把页面删除后，该格会自动回到"未配置"占位。改一格只重建该格 WebView，其余三格不重载。

### 电视端行为

- 首页按【菜单】→「分区展示（2×2 拼接）」进入；2×2 四格同时加载。
- 方向键移动时，目标格青色描边**亮约 0.6 秒后淡出**（未配置的格同样会亮，它此时就是"光标"）；当前分区不做常驻边框——四格都在展示真实页面，一圈常驻亮边会长期压住画面。当前操作对象另有 Toast（"当前分区：xxx"）与选择弹层的标题（"选择第 N 格的页面"）双重提示。
- 四格的 WebView 均设为不可聚焦，方向键 / 确定键由 Activity 全量接管，用于现场选格与选页；页内自动登录与脚本注入照常运行，但网页元素不再抢占遥控器方向键。
- 未配置的分区显示占位文案（`未配置 · 按【确定】选择页面`），不影响其它分区。
- 四个 WebView 同时运行对性能有一定要求，建议只给确实需要同时展示的分区配置内容。

## 五、客户端数据同步机制

### 为什么这样设计

电视常年开机、内容需要随时改，但网络可能不稳定、启动又必须快。因此客户端**只读**服务端数据，并采用「本地缓存 + 版本化增量 + 失败保留」的策略。

### 同步流程

```
启动 → 用本地缓存/兜底内容立即渲染首屏（不等待网络，启动时间可控）
     → 后台发起 GET /api/config?since=<本地version>&epoch=<本地epoch>
         ├─ 304           → 内容无变化，什么都不做
         ├─ 200 + delta   → 按「删除 → 覆盖/新增 → 按 order 重排」合并
         └─ 200 + full    → 首次/代次变化/版本过旧，整体覆盖
     → 有变更才重绘界面并落盘缓存；失败则保留现有内容并显示「离线」
```

### 增量协议

服务端为每次写操作抬高全局 `version`，并为每条页面记录最后变更的 `rev`，删除时留下 `tombstone`：

| 请求条件 | 服务端响应 |
| --- | --- |
| `since` 等于当前 `version` | `304 Not Modified`（空 body，最省流量） |
| `metaRev > since` | 增量里的 `meta`（标题等） |
| 条目 `rev > since` | 增量里的 `upserted` |
| 删除痕迹 `rev > since` | 增量里的 `deletedIds` |
| `orderRev > since` | 增量里的 `order`（完整 id 顺序） |
| 首次 / 删除痕迹已裁剪 / `epoch` 变化 / 版本超前 | 全量 `full` |

> 为什么顺序要单独下发：增量里的 `upserted` 只能表达"某条目内容变了"，无法区分"改了一个字段"和"整体重排了顺序"，所以重排时显式下发完整顺序 `order`，避免客户端排序错乱。

### 可靠性设计

| 场景 | 行为 |
| --- | --- |
| 网络抖动 / 服务器暂时不可用 | 请求自动重试 3 次（指数退避），仍失败则保留缓存内容并显示「离线」 |
| 服务端数据异常（版本回退、代次不一致） | 客户端自动降级为全量重拉，保证最终一致 |
| 进程被杀 / 掉电 | 缓存采用「临时文件 + rename」原子写，不会写出半个文件 |
| 从未成功同步过 | 使用包内 `fallback` 兜底内容，界面照常可用 |

### 缓存位置与内容

`/data/data/com.digitalcenter.tvshow/files/server-config.json`：保存合并后的完整配置 + `version` + `epoch` + `etag`，作为下次增量同步的基准。删除该文件等同于"恢复出厂"，客户端会重新全量拉取（失败则回到包内兜底）。

## 七、自动登录实现说明

`auto_login.js` 以 700ms 为周期轮询页面（最多等待 45s），流程如下：

1. 若命中 `successSelector` → 判定已登录，直接退出；
2. 查找密码框：优先 `passwordSelector`，否则取第一个可见的 `input[type=password]`；
3. 查找用户名框：优先 `usernameSelector`，否则在**同一 `<form>`** 内按 `name/id/placeholder` 关键词（user、account、login、账、用、户、名、邮箱、手机）匹配，仍找不到则取密码框之前最近的可见文本框；
4. 查找登录按钮：优先 `submitSelector`，否则同表单内的 `button[type=submit]`，再按按钮文案（登录/登陆/登入/签到/Login/Sign in）匹配；
5. 写入账号密码：使用原生 `value` setter 并派发 `input`/`change` 事件，**兼容 Vue / React 等受控组件**（已适配 Quasar 前端框架）；
6. 触发提交：点击登录按钮 → 无按钮则 `form.requestSubmit()` → 无表单则模拟 `Enter` 键；
7. **失败重试（电视端防「无限重复登录」）**：三条防线共同生效——
   - **挂起期不重复提交**：若登录按钮处于禁用 / `aria-busy` / 文案命中「登录中 / 提交中 / 验证中 / loading…」，或页面上出现可见的 loading 遮罩，则**本轮不点击**，等它自己出结果（最多等 `maxPendingMs`，默认 25s，超时即停手）。这修掉了"每 5 秒重启一次在途登录请求、页面永远停在『登录中…』"的死循环。
   - **跨重载累计上限**：用 `sessionStorage` 记录该入口已提交过的次数，累计超过 `maxTotalAttempts`（默认 3）就不再自动提交；重新进入该入口会重置。即使页面每次提交后整页刷新，也不会无限循环。
   - **被拒即停手**：5 秒后若账号/密码框仍存在但值已被页面清空（登录被拒的典型特征），立即停止；若登录框消失或命中 `successSelector`（即已登录），清零计数并退出。
   用户可现场按【菜单】→ 刷新页面重新触发一次自动登录。

### 如何为新的登录页补充选择器

1. 电脑浏览器打开该大屏地址，按 `F12`；
2. 在 Elements 面板定位用户名框、密码框、登录按钮，右键 → Copy → Copy selector；
3. 填入 `autoLogin.usernameSelector` / `passwordSelector` / `submitSelector`；
4. 登录成功后的页面元素（如某个专属菜单）可填入 `successSelector`，用于快速判定已登录状态。

### 自动登录（混合方案）

浏览器同源策略下，跨域 `iframe` **无法注入脚本**，所以「自动登录」只对**同源**页面成立。据此提供两种打开方式，顶栏按钮可随时切换（选择记在本机）：

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| **代理**（默认，配了自动登录的入口） | 经服务端反向代理 `/proxy/<入口id>/…` 打开，与客户端同源 → 注入与电视端**完全相同**的 `auto_login.js` 自动填充并提交 | 需要登录的大屏（机房动环、物探中心平台） |
| **直连** | 直接用配置里的原始地址打开 | 无需登录、或代理兼容性不佳时的退路 |

反向代理的约定（`server/proxy.js`，除可选的 `esbuild` 外仅用 Node 内置模块）：

- 路由 `/proxy/<entryId>/<rest...>`，**`entryId` 只能取自 `data.entries` 的 id**（不允许用 URL 参数指定目标，防 SSRF）；
- `/proxy/<id>` 映射到入口 URL 的 **origin 根**，`<rest>` 原样镜像（`http://10.8.11.3/cockpit` → `/proxy/security-cockpit/cockpit`，页内 `/api/x` → 上游 `/api/x`）；
- HTML 只做**属性级**改写；JS/CSS 不做正则改写，改为注入运行时 shim，patch `fetch` / `XMLHttpRequest` / `history` / `WebSocket` / `EventSource`，把指向上游源的地址收敛到代理前缀；
- 属性改写同时覆盖**带引号与不带引号**的写法（现场虚拟化平台就是 `<script src=/global/static/js/index.js>` 这种），并整体吃掉 `scheme://host`（含 `https://`），避免残留成 `https:/proxy/...` 被浏览器解析为不存在的主机；
- 勾选了**旧内核兼容转译**的入口，其 `.js` 响应会先经 `transpile.js` 降级再下发（见下文），其余入口的 JS 原样透传；
- 剥离 `X-Frame-Options` / `CSP` 等阻止嵌套的头；`Location` 不跟随并补前缀；`Set-Cookie` 的 `Path` 做前缀拼接并去掉 `Domain`；文本响应改写后删除 `Content-Encoding`/`Content-Length`；
- 二进制、大文件、`text/event-stream`（SSE）一律流式直通不缓冲；`WebSocket` 升级（含首帧）双向透传；
- 被代理页用脚本 `location.href='/x'` 跳转时会丢前缀（`window.location` 无法被 shim 拦截），服务端在**所有自身路由都没命中之后**按 `Referer` 302 回带前缀的地址兜底；
- 拒绝指向服务端自身的入口（防代理环），并有每入口并发上限；
- **服务端注入自动登录**：对配置了自动登录的入口，代理在返回 HTML 时直接把 `__TV_AUTOLOGIN__` 配置与 `auto_login.js` 注入页面（标记 `__TV_AUTOLOGIN_SERVER__`，客户端据此判重不再重复注入）。这样「强制原址打开」的独立标签页（没有客户端外壳）同样能自动登录。

### history 路由 SPA（`spaHistory`）

Uptime Kuma 这类 **history 路由 SPA** 通过代理打开时会渲染出 SPA 自己的 404（「未找到该页面」）：SPA 路由器启动时直接读 `location.pathname`，看到的是 `/proxy/<id>/dashboard`，匹配不到自己的路由。管理后台勾选「**history 路由 SPA 页面**」后，代理在页面最开头用原生 `history.replaceState` 把前缀从地址剥离（`__TV_STRIP__` 标记执行结果），SPA 的 `pushState` 仍会被 shim 加回前缀以保证刷新可用，后退/前进（popstate）时再同步剥离。注意：传统多页站点不要开启，剥前缀会让相对路径的表单/链接逃出代理（仅 GET 有兜底）。

另有两处配套保障：① 文档导航请求（`Accept: text/html`）不下发 `If-None-Match`/`If-Modified-Since`——上游的 ETag 只反映上游原始内容，放行会让浏览器拿 304 永远沿用改写规则过期前的旧 HTML；② 改写后的 HTML 统一带 `Cache-Control: no-cache`，强制每次回源拿到新鲜内容。

### 强制原址打开（`openOriginal`）

依赖本地视频插件的页面（如海康 iVMS 的 `preview.asp`）无法在缩放的内嵌壳里正常工作——插件视频是操作系统原生窗口，不跟随 CSS 缩放。管理后台编辑页面时勾选「**强制原址打开**」后：

- 点击卡片**不进内嵌壳**，直接在新标签页打开；配了自动登录的入口走代理地址（`/proxy/<id>/…`），由服务端注入的脚本自动填表登录，无需人工输入；
- 该入口**自动跳过轮询展示**（避免轮播时不停弹新标签）；
- 观看端建议 F11 全屏 + 浏览器缩放 100%，视频窗格即可与宫格贴合；视频解码仍需观看电脑安装海康 WebComponentsKit 等本地插件。

### 旧内核兼容转译（`compatTranspile`）

**解决什么问题**：老电视的系统 WebView 内核被夹在 Chrome 57~71（现场的小米电视为 **Chrome 66**），而现代大屏前端产物普遍用了更高版本才支持的语法（`??` 需 80、公有类字段 `class A { x = 1 }` 需 72）。这类是**硬语法错误**，解析即抛，表现为**整页白屏**——polyfill 无法补救。典型例子：虚拟化集群页（`10.8.16.10:30000`）的 `index.js` 有 11 处公有类字段，Chrome 66 直接白屏。

**怎么解决**：在**服务端代理**这一层做语法降级——把 JS 降级到目标内核即可，**不需要目标大屏系统配合改造**；电视端只要改为经该代理加载（客户端 1.2 起已内置，见下），**无需重装以外的任何现场操作**。

- **前提**：服务器能联网，在 `server/` 目录执行过 `npm install`（安装 `esbuild@0.28.2`，唯一的 npm 依赖）。**没装也能跑**：`transpile.isAvailable()` 返回 false，代理自动退回「原样透传」，服务端照常零依赖启动。
- **怎么开**：管理后台编辑该入口 → 勾选「**旧内核兼容转译（电视端白屏修复）**」，可选填 `compatTarget`（默认 `chrome66`，格式如 `chrome66` / `es2019` / `safari13`，填错会被 400 拒绝并提示）。落盘字段：`compatTranspile: true` + `compatTarget: "chrome66"`。
- **只对走代理的入口生效**：电视机侧必须让该入口经服务端代理加载。**客户端 1.2 起**：入口勾选兼容转译后，电视端展示页与 2×2 分区页都会自动改为加载 `{服务器}/proxy/<id>/<上游路径>`（[displayUrlOf()](file:///root/tv-show/app/src/main/java/com/digitalcenter/tvshow/config/AppConfig.kt#L42-L62)），无需人工干预；电脑端则是点开即走代理。**1.1 及更早的电视端没有代理能力**（直连 `entry.url`），服务端转译无从生效——这是 1.2 必须升级的原因。
- **两步手段**：
  1. **语法转译**（`esbuild.transformSync(code, { target, minify: true })`）：吃掉 `??` / `?.` / 类字段 / 静态块等，压过的产物标识符重命名不影响运行时回调注册（无 DI 风险）；输入本身已是压缩产物，转译后体积仅 **+1.9%**（3.32MB → 3.38MB，约 1.1s）——若关掉 `minify` 反而会膨胀 40%，所以必须开。
  2. **运行时垫片**（ES5 写法、存在性守卫，注入在业务脚本之前）：补齐 `globalThis`、`String.replaceAll`、`String.matchAll`、`String.trimStart/trimEnd`、`Array.prototype.flat/flatMap`、`Promise.allSettled`，以及 64 位 / 新数组 API：`BigInt`（含 `asIntN`/`asUintN`）、`DataView.prototype.setBigUint64/getBigUint64`、`Array/String.prototype.at`、`findLast/findLastIndex/toReversed/toSorted/toSpliced/with`、`Object.fromEntries/hasOwn`、`Promise.any`、`queueMicrotask`。清单来自对两个站点产物的实测命中，不是凭经验堆的。
     - 其中 `BigInt` 是**AI 大模型页（Uptime Kuma）白屏的根因**：该站点把 `webidl-conversions` 一并打包，**模块初始化阶段**就读 `BigInt.asUintN`，Chrome 66 下 `ReferenceError` 直接中断整个 bundle 初始化 → 全白且连报错面板都拿不到牌；`.at(-1)` 则用在心跳列表渲染。垫片用「值都能转成 Number」的等价实现（该模块的用途就是把宽度受限的整数转成 JS 数字，帧长度编码也只在 < 2^53 范围内）。
- **缓存**：内容寻址（`sha256(target + 内容)` 取前 32 位）落盘在 `server/.cache/transpile`（可用 `TVSHOW_TRANSPILE_CACHE` 覆盖），内存 LRU 48MB + 磁盘 256MB（按 mtime 淘汰）。命中的 `.js` 即使带 `?cb=1` 这类查询串也只算一次转译。头行校验不过（版本 / target / 原长不符）即删除重算，缓存损坏可自愈。
- **三层兜底即回退**：esbuild 不可用 / `transform` 抛错 / 原文不是合法 UTF-8 → **一律回退原文**，绝不返回 502/503。最坏情况退化成「没开这个开关」。
- **取舍（重要）**：开了转译的入口，其 `.js` 请求**不下发 `If-None-Match`/`If-Modified-Since` 条件头**，并统一 `Cache-Control: no-cache`——因为上游的 ETag 只反映**上游原始内容**，若放行 304，浏览器会一直沿用旧产物，转译结果永远到不了页面。代价是这类 JS 每次回源（有服务端缓存兜底，不重复转译）。
- **踩过的坑（客户端缓存必须逐字段写全）**：电视机侧把配置缓存在 `files/server-config.json`（[ConfigStore.kt](file:///root/tv-show/app/src/main/java/com/digitalcenter/tvshow/net/ConfigStore.kt#L88-L109)）。缓存写入是**手写字段清单**，漏写任何「解析时会读」的字段，下次启动就会回落到默认值；而此时服务端往往因为版本没变返回 **304**，该字段**再也补不回来**。`compatTranspile` 就曾因此丢失：服务端明明下发为 `true`，电视端因缓存缺字段而按 `false` 直连，白屏照旧。修复后如需让**已装机的旧版本**重新拿到该字段，用 `POST /api/admin/epoch/bump` 抬一次 epoch，所有客户端下次同步会走**全量**。
- **现场自诊断（客户端 1.3 起）**：大屏页按【菜单】，信息浮层第二行是**真实加载地址**、第三行标注 **`兼容代理` / `直连`** —— 一眼可确认客户端有没有按预期走代理（若仍显示直连或显示上游地址，说明 APK 未升级或配置未同步）；页面若白屏，「页面无法显示」面板会**直接附上最近一条脚本错误**（含 `SyntaxError` 等，来源文件与行号），现场无 adb 也能定位。
- **状态自查**：`GET /api/admin/health` 的 `transpile` 字段给出 `{ available, version, reason, defaultTarget, cacheDir, stats:{ hits, misses, failures, outBytes } }`。

### 摄像头画面墙（`type: camera`）

把入口的 `type` 设为 `camera` 后，卡片点开就是**内置画面墙**，直接播放摄像机实时画面——不需要海康本地插件、不需要登录页、不需要外网地址，属于「点开即看」的傻瓜式入口。

- **怎么用（电视端）**：默认 3×3 宫格，方向键选格、【确定】放大为 1×1（再按回到宫格）、【菜单】可切换 3×3 / 1×1、重新连接或返回首页、【返回】回首页；单画面时方向键切换上一路/下一路。（电脑端客户端同款功能，快捷键为【M】切换布局、【R】重连，鼠标点击格子放大/还原。）
- **两种布局**：只做 3×3（多路总览）与 1×1（单路放大，取主码流更清晰），不提供其它布局。
- **技术路线**：服务端用 ffmpeg 把摄像机的 RTSP 流（H.265）实时转成 MJPEG。电脑端与预览页用 `<img>` 承载；**电视端不引第三方库**，用 `HttpURLConnection` 直接拉 `multipart/x-mixed-replace`，按 JPEG 的 `SOI(FFD8)` / `EOI(FFD9)` 标记切帧后交给 `ImageView`（解码复用同一块 `Bitmap` + `RGB_565`，避免 10fps 长跑时每帧新分配几 MB 触发 GC 卡顿），断流后 3 秒自动重连。因此整条链路**零第三方播放库**，也没有原生插件窗口不跟随缩放的问题。
- **为什么按行合成**：浏览器对同一域名只并发 6 条 HTTP/1.1 连接，而 MJPEG 是永不结束的长连接——8 路画面会占满 6 条后把其余请求永久排队，表现为「每次随机有几格永远黑屏」。因此 3×3 墙面在**服务端按行用 ffmpeg `hstack` 把 3 路拼成一条 1920×360 画面**（`/cam/wall.mjpg?row=1..3`），整面墙只占 3 条连接；离线通道用黑帧占位，避免单路连不上把同行的好画面一起拖黑。
- **进程模型**：3×3 每行一个 ffmpeg 进程，1×1 每「摄像头 + 画质」一个进程，多客户端同时观看只占一份 CPU；无客户端时 8 秒自动回收；异常退出按 1s→8s 退避重启（重启前重探通道在线状态，掉线恢复的通道可重新入画）；全局上限 14 个进程。切换布局会立即断开旧连接，服务端随即回收。
- **配置位置**：摄像头的 RTSP 地址与账号密码只写在服务端 `server/data/config.json` 的 `cameras` 字段（管理后台**不暴露**，避免误改），结构如下：

```json
"cameras": {
  "enabled": true,
  "host": "10.8.12.131",
  "port": 554,
  "username": "show",
  "password": "********",
  "count": 8,
  "titles": { "1": "机房北墙", "2": "机房东墙" },
  "logo": "wutan-logo.png",
  "logoCell": 5
}
```

- **品牌格**：`logo` 是 3×3 中某一格要放的图片（绝对路径或相对项目根目录），`logoCell` 指定格子序号（1 起，从左到右、从上到下，默认 5 即第二行第二列）。该格为**纯黑底 + 居中品牌图**，尺寸取格子的 60%，其余摄像头依次往后挪一格，8 路仍全部上墙。`logo` 留空或文件不存在时该格为纯黑。改动后需重启服务生效。
  图片**不由 ffmpeg 合成进视频流**，而是由客户端叠在黑底上缩放：墙面是 `object-fit: fill`，格子宽高比（实测 1.895）不等于 16:9，合成进视频的图会被横向抻宽约 7.5%，比例对不上原素材。
  - 电脑端：图片经 `/cam/logo.png` 下发，用 CSS `object-fit: contain` 缩放，比例与原素材严格一致；
  - 电视端：图片已打进 APK（`app/src/main/res/drawable/wutan_logo.png`），用 `FIT_CENTER` + `scale 0.6` 绘制，离线可用、不依赖网络请求。
  两端的「第几格放什么」都由服务端 `/api/cameras` 的 `cells` 字段决定（正数为摄像头编号、`'logo'` 为品牌格、`null` 为空位），避免两端各自推算导致图文错位。

- **防越权**：客户端只能按**摄像头编号**点播（`/cam/1.mjpg`），RTSP 地址与凭据始终留在服务端，不会被前端拿到或改写成任意地址。
- **前置依赖**：服务器需安装 ffmpeg（`yum install -y ffmpeg`）。画面墙入口会自动跳过轮询展示与 2×2 分区拼接（它们是 iframe 机制，不吃内置整屏页面）。

### 已知限制

1. **代理兼容性**：目标页若强依赖 `location.origin`、把上游地址硬编码在 JS 里、或强校验 `Referer`，仍可能异常——保留**直连模式**作为退路。
2. **直连模式无法自动登录**：跨域限制，只能手动登录一次并依赖浏览器 Cookie 持久化。
3. **同源风险（既有设计遗留）**：被代理页面与 `/api/admin/*`、`/api/config` 同源，理论上可读取配置（含明文口令）。这是「管理后台内网免登录 + `/api/config` 必须下发口令给自动登录」的既有属性，非电脑端引入；缓解办法仍是**用防火墙限制 18080 的访问范围**（见第十二节）。
4. **内嵌页面聚焦后快捷键失效**：浏览器机制限制，靠鼠标按钮兜底。
5. **旧内核兼容转译的边界**：它只解决**语法**（`??` / `?.` / 类字段等）与少量**运行时 API**（垫片清单内）。目标页若用了清单外的新 API（如 `Object.hasOwn`、`structuredClone`、`Array.prototype.at`），仍可能在老内核上报错；此时按报错补充垫片，或改用「让目标系统提供兼容构建」。另外它只在**经代理加载**时生效（客户端 1.2 起对勾选了该开关的入口自动走代理），且首屏第一次转译大 JS（3MB 级）会有约 1 秒延迟（之后走缓存）。
6. **白屏提示文案里的内核版本是通用值**：电视端「页面无法显示」面板中「至少需要 Chrome/80」是客户端的**通用提示文案**（不区分具体页面），不等于该页面的真实要求；它表示"页面已加载但没有可显示内容"，在开启兼容转译并升级到 1.2 后应不再出现。

### 极速模式（截图展示，电视端与电脑端通用）

把"渲染"从播放端搬到服务器：服务端用无头 Chromium 打开真实页面并按该页配置周期截图，电视/电脑端只显示一张不断刷新的 JPEG。重型监控大盘（动环、虚拟化、AI 等）在老内核电视上从此零 JS 执行、零 WebSocket，首屏 ≤3s（热）/约 5~10s（冷，之后恒定）。

- **开关（本机，默认关）**：电视端在首页【菜单】或展示页/分区页【菜单】弹窗里「极速模式：关/开」（翻转后立即重载）；电脑端在「更多 ▾」菜单里同名开关（存 `localStorage`）。
- **参数（服务端统一配置）**：管理后台每个入口的「极速模式」区块可逐页设置 `turboEnabled`（是否参与，默认参与）/ `turboIntervalSec`（刷新率 0.2~60s，一位小数，预置 0.2/0.5/1/2/3/5/10/30/60 档位+可自定义）/ `turboQuality`（JPEG 质量 50~95）。动画型页面推荐 **0.5s + 质量 85**。设置随配置同步下发，服务端改了下一帧立即生效。
- **不参与**：`type=camera` 机房画面墙（原生 MJPEG 已是最轻路径）。
- **无人观看自动停采**：包装页每 5s 心跳；停止观看 30s 后暂停采集（标签与会话保留 30 分钟热保活，回来 ≤3s 恢复），期满无人再关闭。
- **HTTP API**：`GET /shot/<id>/view`（包装页）、`GET /shot/<id>/frame.jpg`（最新帧，无帧 503）、`GET /shot/<id>/meta.json`（状态/帧时间戳/当前周期/质量）、`POST /shot/<id>/beat`（心跳）。登录复用入口 `autoLogin` 在服务端无头完成，敏感字段不出现在任何 /shot 响应。
- **依赖（可选）**：`playwright-core` + Chromium 二进制；缺失时 /shot 返回降级包装页（附跳转真实页面），服务端本体照常启动。安装：

```bash
cd server && npm install            # 安装 playwright-core
PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright \
  npx playwright install chromium   # 国内官方源失败时用 npmmirror 镜像
```

- **健康检查**：`/api/admin/health` 增 `shot: {available, reason, activeEntries}` 字段；信息浮层显示「极速模式」与帧龄，现场可核对采集是否存活。

## 九、多设备互控（远程控制）

1.8 新增：用一台平板（或任意电脑）的浏览器打开**独立控制台**，远程控制全场设备显示哪个页面、轮询或 2×2 分屏——设备身份与 IP 解耦，指令 3 秒内送达，离线存储转发，重启自动恢复。

### 页面分工（控制与显示分离）

| 页面 / 端 | 角色 | 说明 |
| --- | --- | --- |
| `/console` **独立控制台** | 纯控制端 | 单文件页面，平板存书签即用；**自身不注册为受控设备**，操作者永远不会被自己下发的指令影响 |
| `/` 显示端首页 | 纯显示端 | 就是原来的电脑客户端，界面与 1.7 一致；打开即注册，被控时**只切画面、不锁鼠标** |
| 电视 APK 1.8+ | 纯显示端 | 被控时切画面 + 锁定遥控按键（无人值守防误按）+「远程被控」角标 |

服务端不区分角色：`/api/ctl/send` 谁调用都一样（内网免鉴权，防火墙限源从建议升级为**必须**）。

### 显示端行为（电脑 / 平板 / 电视）

- **打开即注册**：设备身份本地生成、终身不变（与 IP 无关），默认名「新设备-xxxx」，在控制台改名。
- **指令即生效（≤3 秒）**：`show` 进指定大屏（画面墙入口进画面墙，「强制原址打开」入口仍内嵌）；`rotate` 写入本机轮询设置并开始播放；`zone` 写入分区设置进入 2×2；`home` 回首页；`refresh` 刷新当前画面；`sync` 强制同步内容。
- **电脑 / 平板显示端不锁定**：被控只是"远程帮你换了台"，鼠标 / 键盘 / 顶栏按钮**始终可用**——现场随时可以本地操作，控制台卡片会如实显示实际画面，需要时再下发纠偏。
- **电视端锁定**：被控时遥控器方向 / 确定 / 返回键被拦截（仅 Toast 提示），【菜单】键例外——菜单首项「控制模式：本地控制 ▸ 远程被控」，**退出远程被控需二次确认**（默认焦点「继续受控」防误触），确认后画面保持、按键立即恢复；控制端再下发即自动切回。
- **断电 / 重开**：受控 + 「开机恢复」开的设备重启后自动回到设定画面（电视 / 电脑默认开，平板默认关，控制台逐台可改）；本地控制的设备重启行为与 1.7 一致。
- 引用的页面已被删除：跳过 / 回首页，失败原因随心跳上报，控制台卡片显示。

### 独立控制台（/console）

- **设备卡片**：勾选框、名称（点按改名）、类型（TV/PC/平板）、模式（远程被控/本地控制）、在线状态点、实际画面摘要、待送达角标、「开机恢复」开关。
- **卡片右侧单台快捷操作**：「显示页面」下拉、「轮询…」「分屏…」「取消控制」（二次确认）、「改名」「开机恢复」——**无需勾选，对这张卡片的设备直接下发**，单台控制一步到位。
- **底部群组操作条**：勾选（或「全选」）后一键执行——显示页面下拉、「轮询…」（间隔预设 + 页面多选调序 + **多屏同步切换默认不勾**）、「2×2 分屏…」（四格下拉含「不使用」）、回首页、**取消控制（二次确认，设备交还本地）**、刷新当前页、强制同步。
- **场景预设**：场景条常驻顶部——「＋ 存为场景…」捕获当前全场状态（受控设备记指令、本地设备记当前画面，离线设备跳过）；点「▶ 场景名」一键恢复全馆现场（离线设备补投递，显示"已应用 x/y"）；管理里重命名 / 删除。

### 与本机设置的关系

指令的实现方式是「**把服务端期望值写进本机设置，再进入对应模式**」：无指令时行为与 1.7 完全一致；交还本地后这些值就是本机设置，现场可随意改；控制端再次下发即纠偏。两套机制无缝衔接。

## 十、电脑端预览（免安装测试）

`dist/preview.html` 是一个**单文件**预览页，零外部依赖，由服务端自身托管在 **`/preview`**（**不需要另起 8099 之类的第二个端口**）：

```
http://<服务器IP>:18080/preview
```

也仍可直接双击用 Chrome / Edge / Firefox 打开（或从电脑端首页顶栏「更多 ▾」→「电视端预览」跳转）。它按 **1:1** 渲染 1920×1080 的「电视舞台」，1:1 复现 App 的界面与交互。

### 分辨率（重点）

预览页与电视上的真实页面**都保证不低于 1920×1080**：

| 对象 | 分辨率 | 说明 |
| --- | --- | --- |
| 预览页舞台 | 1920×1080 CSS px | 默认 **1:1** 显示，实际渲染尺寸就是 1920×1080，**不会因为浏览器窗口小而缩到 1920×1080 以下**；窗口不够大时出现滚动条 |
| 预览页 WebView 区 | 1920×1080 CSS px | 与 App 内 WebView 的 CSS 视口一致 |
| App 内 WebView | ≥1920×1080 CSS px | 通过密度重写保证，见下方说明 |

窗口较小时想快速看全貌，点工具栏的「1:1（1920×1080）」按钮可切换为「适应窗口」（会缩小，仅供总览）。

### 访问方式（单端口，推荐）

预览页由服务端直接托管，**只需启动 `node server/server.js`**（默认 18080），无需再起任何静态文件服务：

```
http://<服务器IP>:18080/preview
```

用 HTTP 方式而非 `file://` 打开的好处：内嵌的真实大屏页面（`10.8.11.4:1111` 等）在 `file://` 下会被浏览器同源策略拦截、无法预览外观。

> 轮询与分区设置存在浏览器 `localStorage` 里；`file://` 打开时浏览器可能禁用存储，此时设置只在当前页面有效，**建议用上面的 HTTP 方式打开**（与电视端持久化行为一致）。

> 预览页改版后需重新生成：`node tools/build-preview.mjs`（服务端每次请求都读盘，无需重启）。

### 在真实大屏页面上测注入脚本

出于浏览器同源策略，预览页**无法**向跨域 iframe 注入脚本，所以内嵌的真实大屏页面仅作视觉参考。要测试真实页面的自动登录与遥控器导航：

1. 点击预览页右上角「真实页面注入脚本」，面板中会给出与 App 内**完全一致**的注入代码（自动带上 `config.json` 里的账号密码）；
2. 新标签页打开真实大屏地址，按 `F12` 打开控制台，粘贴代码回车；
3. 或把面板里的「书签脚本」拖到浏览器书签栏，在真实页面上点一下即可注入。

### 与 App 保持同步

配置与注入脚本改完后，重新生成预览页即可（会读取工程内真实文件，不会出现两份代码走样）：

```bash
node tools/build-preview.mjs
```

> 预览页使用与 Android 相同的尺寸换算：舞台 1920×1080 对应电视的 960dp 宽（2 倍密度），大屏区域为 1920×1080 CSS 视口，因此卡片尺寸、间距、字号与 APK 内一致。

> 预览页会按 `config.json` 里的 `serverBaseUrl` 连服务端：**先用内置兜底内容渲染，再异步增量同步**，顶栏「配置来源」标识显示当前数据来自服务器还是兜底——这正是电视端的行为。若只想看兜底布局，把 `serverBaseUrl` 置空即可。

### 首页宫格布局规则

- **列数**：按屏幕宽度自适应，1080p 电视（960dp 宽）固定 3 列。
- **行数**：按入口数量自动换行。**6 个入口即 2 行 × 3 列**，全部一屏完整显示，无需滚动。
- **卡片高度自适应**：按行数均分栅格可用高度（下限 164dp / 上限 260dp）。入口少时卡片自动变高铺满，入口多时收到下限并由 ScrollView 滚动，避免出现大片留白或内容被压缩。
- **焦点放大不被裁**：栅格预留了内边距（横向 10dp / 纵向 16dp）并关闭逐层裁剪，因此最左、最右、首行、末行卡片在放大 1.05 倍后边框与发光都完整可见。

新增入口只需在 `config.json` 的 `entries` 里追加一项，布局会自动重排。

### 客户端依赖

**不引入任何第三方库**：HTTP 用平台自带 `HttpURLConnection`，JSON 沿用 `org.json`，
线程用 `ExecutorService` + `Handler`，因此 `app/build.gradle.kts` 依赖仍只有

### 关键实现要点

- **网络与 WebView**：已在 `AndroidManifest.xml` 申请 `INTERNET` 等权限；`network_security_config.xml` 放行明文 HTTP（内网大屏多为 `http`），并信任用户 CA；WebView 开启 JS、DOM Storage、混合内容放行、禁用文件访问、`mediaPlaybackRequiresUserGesture=false`。
- **遥控器事件分发**：`WebDisplayActivity.dispatchKeyEvent` 负责 返回/菜单 键，其余方向键与确定键透传给 WebView 并由 `tv_nav.js` 以捕获阶段监听 `keydown` 拦截处理；任何按键到达时若 WebView 失焦会自动重新聚焦，保证遥控器「按下去就有反应」。
- **焦点导航算法**：候选元素分两级——**强交互层**（语义明确的 `button` / `a[href]` / `input` / `select` / `role=button` / `onclick` 等）与**兜底层**（常见可点击 class，以及「声明了 `cursor:pointer` 的元素」）。两层按“层级惩罚分”**统一打分**：兜底层加固定惩罚（700），语义控件优先，但不会跳过明显更近的可点元素。方向按下式打分取最优：

  ```
  score = 主方向距离 + 2.4 × 垂直偏移 + 层级惩罚
  ```

  为什么需要「声明了 `cursor:pointer` 的元素」这一层：大屏页面上大量可点击元素是普通 `div`/`h3`/`span`，既无语义标签也无 `tabindex`，只靠 `cursor:pointer` 表示可点（例如存储大屏编辑模式下的存储池名、服务器区，以及可点击的图表扇区）。但 `cursor` 是**继承属性**，父级设了 `pointer` 其所有子节点都会继承，直接用 `cursor === 'pointer'` 会把 `h1`/`span`/`i` 等装饰节点全部算进来（实测某页面虚报到 64 个）。因此只取「声明起点」：**自身 `pointer` 且父级（跳过 SVG 内部）不是 `pointer`**，同一页面即收敛到 11 个（普通模式）/ 21 个（编辑模式）真实目标。

  另外 `div`/`h3`/`svg <path>` 默认不可聚焦、`focus()` 会静默失败，导航引擎会自动补 `tabindex="-1"`；SVG 图形不支持 `outline`/`box-shadow`，焦点样式对 SVG 元素改用 `drop-shadow` 发光以保证可见。
- **稳定性**：网络错误、HTTP 4xx/5xx、证书错误均会进入错误面板并自动把焦点给到【确定重新加载】；退出应用时完整销毁 WebView，避免内存泄漏；两页面均支持横屏全屏、常亮不息屏。
- **大屏分辨率适配（WebView CSS 视口）**：Android 电视在 1080p 下通常上报 2 倍密度，WebView 的 CSS 视口因此只有 960×540，页面会按手机/平板布局渲染，大屏设计稿被压扁或触发响应式降级。`WebDisplayActivity.createDisplayWebView()` 把 WebView 的密度重写为 `屏幕物理宽度 / 1920`：

  | 电视分辨率 | densityDpi | CSS 视口 | 效果 |
  | --- | --- | --- | --- |
  | 1920×1080 | 160（density 1.0） | 1920×1080 | 1 CSS px = 1 物理像素，最清晰 |
  | 3840×2160 | 320（density 2.0） | 1920×1080 | 内容等比放大铺满，避免只占左上角 |
  | 1280×720 | 107（density 0.67） | 1920×1080 | 向下缩放铺满 |

  配合 `useWideViewPort` + `loadWithOverviewMode`，页面拿到的 CSS 视口在任何 16:9 电视上都不低于 1920×1080，且始终铺满屏幕。若页面内容仍比视口宽（例如按 2560 固定宽度设计），`autoFit` 会自动再缩放以适配；也可用 `scale` 固定缩放，或在大屏页按【菜单】→ 放大/缩小 实时调整。
- **稳定性**：网络错误、HTTP 4xx/5xx、证书错误均会进入错误面板并自动把焦点给到【确定重新加载】；退出应用时完整销毁 WebView，避免内存泄漏；两页面均支持横屏全屏、常亮不息屏。

## 十二、注意事项

### 服务端与安全

1. **管理后台内网免鉴权（重要）**：按交付约定不设登录，因此**同网段任何人都能打开后台并修改内容**。请务必：
   - 只在内网部署，不要映射到公网；
   - 用防火墙限制来源网段（只允许运维机访问 18080 端口）；
   - 需要更严的隔离时，用 `--host 127.0.0.1` 只监听本机，前面挂一个带认证的反向代理。
2. **数据备份**：全部数据就是单个 `server/data/config.json`，定期备份该文件即可（服务端每次写入会自动保留 `.bak`，主文件损坏时启动会自动回退）。删除该文件后再启动会重新生成初始数据。
3. **服务端地址是打包内置的**：换服务器需要改 `app/src/main/assets/config.json` 的 `serverBaseUrl` 后重新出包；现场临时切换可把同名引导文件推到设备外部目录（见第二节），无需重装。
4. **密码明文存放**：自动登录账号密码以明文存在于服务端 `server/data/config.json`，并会下发到客户端缓存。请限制服务端的访问范围。

### 客户端与页面

5. **必须使用 `http` 或可信证书的 `https`**：内网自签名证书请将该入口的 `allowInsecureSsl` 置为 `true`，否则会停在证书错误页。生产环境更建议为内网大屏配置受信任证书。
6. **首次访问与 Cookie**：自动登录依赖页面的正常登录流程，登录态由页面自身的 Cookie / localStorage 保存。若大屏系统本身不支持长期登录态，每次进入大屏页面都会自动重新登录一次，属正常现象。
7. **签名口令**：正式交付前建议修改 `gradle.properties` 与 `keystore/` 中的默认口令，或替换为贵方自有证书。
8. **WebView 内核版本（电视端白屏的头号原因）**：电视机的网页渲染能力由**系统自带的「Android System WebView」内核版本**决定，与电视机型年份强相关（本应用走系统 WebView，无法自带内核）。老电视（如小米电视 Android 6.0.1 / MIUI TV 1.3.127）的内核通常被夹在 **Chrome 57~71**，而现代大屏前端会用到更高版本才支持的语法：
   - `??`（空值合并，需 **Chrome 80**）、类字段 `class A { x = 1 }`（需 **72**）属于**硬语法错误**，解析即失败 → **整页白屏，polyfill 无法补救**；
   - `.at()`（92）、`replaceAll()`（85）、`Promise.allSettled`（76）等属运行时 API，可 polyfill（服务端在开启兼容转译时会自动补，见下）。

   **如何现场确认内核版本**：在大屏页按【菜单】，信息浮层右上角会显示 `内核 Chrome/xx`。**xx < 80 出现白屏基本可确定是内核问题**（例：虚拟化集群页需 ≥72、AI 大模型页需 ≥80）。

   **无内容 / 天白屏时的兜底**：应用会在页面加载后连续两轮探测可视内容，若仍判定为空白，则用「页面无法显示」提示层替代白板，屏幕提示 `菜单 刷新重试 · 返回 退出`，不再让现场只看到一片白。

   **处理路径**（按可行性排序）：
   1. **在管理后台为该入口勾选「旧内核兼容转译」**（推荐）——服务端代理把该页 JS 降级到 `chrome66` 并注入运行时垫片，无需改目标系统、无需重装 APK；前提是服务器装过 `esbuild` 且该入口走**代理模式**，详见「八、电脑浏览器客户端 → 旧内核兼容转译」；
   2. 在电视上打开 **Google Play / 应用商店 → 搜索「Android System WebView」（或「Chrome」）→ 更新到最新版**（最省事，但部分老机型商店里没有该应用）；
   3. 通过 `adb install -r` 侧载较新的 WebView APK（需与系统签名兼容，风险较高，可能无法安装）；
   4. **让目标大屏系统提供兼容构建**（关掉 `??` / 类字段、降低构建 target），从源头根治（需要对方团队配合）；
   5. 若该入口不要求嵌入，可在管理后台为其勾选「强制原址打开」，改为在系统浏览器中打开（浏览器内核往往比系统 WebView 新）。
9. **缩放调整建议**：先看默认效果。若页面留有黑边或内容偏小，优先调整该入口的 `scale`（如 90 / 110）；若页面明显被裁切，确认 `autoFit` 为 `true`。临时调整可在页面内按【菜单】→ 放大/缩小（不写回服务端）。
10. **页面自身声明了固定 viewport 宽度**：若页面在 `<meta name="viewport">` 中写了固定的 `width`（而非 `device-width`），会覆盖 WebView 给出的 1920×1080 视口，此时用该入口的 `scale` / `autoFit` 调整，或把页面 viewport 改为 `width=device-width`。
11. **如何确认电视上的实际视口**：可临时用 Chrome 远程调试（`chrome://inspect`）查看 `window.innerWidth`；1080p 电视上正常应为 1920。启动日志里也会打印「屏幕 …px, densityDpi=… → WebView CSS 视口 …」。
12. **焦点落在图表上**：可点击的图表元素（如 SVG 扇区）会被纳入导航。若某个大屏的图表区域不需要遥控器操作，或页面用假 `cursor:pointer` 标记了整块装饰区域，可在页面中为可交互节点显式添加 `role="button"` 或 `tabindex="0"`（这些会被识别为强交互元素），并避免给纯装饰容器设置 `cursor:pointer`。
13. **引导配置的外部覆盖路径**：外部引导文件放在应用私有目录 `/sdcard/Android/data/com.digitalcenter.tvshow/files/config.json`（Android 10 及以上无需额外授权）；用 `adb push` 前请先启动一次应用，让目录自动创建。
14. **多屏部署**：所有电视共用同一个服务端，改一次内容全部生效；新增/调整入口只需在管理后台操作，无需逐台维护文件。
15. **轮询进入即播，不必先设置**：按【菜单】→「轮询展示」会**立即开始轮播**；这台电视从未选过轮询页面时，默认让服务端全部页面参与（点开即用）。要改设置，在**轮询播放页再按一次【菜单】**→「轮询设置」。其中「开机自动播放」默认关闭，只决定应用启动时是否自动进入轮询；不需要自动播放时保持关闭即可，随时可用【菜单】手动进入。
16. **轮询/分区默认是「各台设备各自配置」的**（服务端不保存展示策略）；**需要"改一次全场生效"时用多设备互控**（第九节）：控制端对单台 / 多台 / 全部设备下发显示、轮询、分屏或场景，指令写入各设备本机设置并立即生效——这正是指令的实现方式，与本机设置无缝衔接。
17. **分区展示是「进入即配置」**：首页【菜单】→「分区展示（2×2 拼接）」直接进页面，方向键选格、按【确定】为该格选页面，**没有独立的"分区设置"界面**。四格的 WebView 均不可聚焦，因此分区页内网页元素不再响应遥控器方向键（这是为现场选格让路的取舍），页内自动登录与脚本注入仍照常运行。另外四格**始终按 1920×1080 的分区视口渲染**（客户端按每格物理宽度重写 WebView 密度）：在 3840×2160 的拼接屏上每格正好 1920×1080，1:1 无损；在普通 1920×1080 电视上每格只有 960×540 物理像素，页面会被整体等比缩小到 50%（布局不变、只是变小，字会很小）。若要在大屏上 1:1 呈现，请使用 4 块 1920×1080 拼接的 3840×2160 屏幕。
18. **四个 WebView 同时运行有性能开销**：分区展示会同时加载最多 4 个大屏页面，低配电视可能出现卡顿、内存紧张甚至 WebView 被系统回收。建议：只给确实需要同时展示的格位选择页面（未选择的格位不创建 WebView），另外三个分区尽量选轻量页面，并在真机上确认长时间运行的稳定性。轮询播放是单 WebView 逐页切换，开销与普通大屏页一致。

6. 确认管理页**只有**页面管理与系统标题两块，没有轮询/分区面板（这两项归客户端）；
7. 回到首页 `/`，确认卡片数量与后台页面数一致、标题居中、时钟走动；
8. 点一张**无需登录**的卡片，确认页面在浏览器里正常显示、**鼠标可直接点击页面内的元素**，`Esc` 返回首页；
9. 点一张**配了自动登录**的卡片（默认走代理），确认顶栏显示「代理」、页面**自动完成登录**；
   若目标页异常，点顶栏「直连」切换后重试，确认两种方式都能打开（切换结果会记住）；
10. 点「轮询展示」确认**直接开始轮播**，状态条显示「轮询播放中 · 第 x/n 页 · Ns 后切换」，`空格` 可暂停/继续；
   进「本机设置」改间隔与参与页面（↑↓ 调序），确认刷新页面后设置仍在；
11. 点「分区展示」：点击某格「选择页面」为它指定大屏，确认其余格不重载；方向键移动确认只有高亮变化（四格画面不闪断）；
12. 复制一份 `server/data/config.json` 作为初始备份。

> **（可选）启用旧内核兼容转译时另查**：`cd server && npm install` 装好 `esbuild` 后重启服务端；
> 访问 `/api/admin/health`，确认 `transpile.available` 为 `true`、`version` 有值；
> 在 `/setting` 给目标入口勾选「旧内核兼容转译」并保存；
> 浏览器打开 `http://<服务器IP>:18080/proxy/<入口id>/<页面路径>`，确认页面正常且控制台无 `Unexpected token` 类语法报错。

### 电视端（装包后确认）

13. 启动应用：**首屏是否立即出内容**（不等网络），底栏右侧是否显示同步状态；
14. 服务器上把某个页面标题改掉 → 电视上按【菜单】→「立即同步配置」→ 底栏提示「已从服务器更新到 vN」且标题已变；
15. 在管理后台新增／删除一个页面 → 电视端同步后入口数量随之变化，**全程无需重装**；
16. **停掉服务端**后重启电视应用：仍显示上次同步的内容并标注「离线」；恢复服务端后按【菜单】可继续同步；
17. **首页【菜单】是否弹出控制菜单**（4 项：立即同步配置 / 轮询展示 / 分区展示（2×2 拼接） / 关闭）——若按【菜单】没有反应，先确认遥控器该键发出的是 `KEYCODE_MENU`（可用 `adb shell getevent` 观察）；
18. **轮询进入即播**：按【菜单】→「轮询展示」，是否**直接开始轮播**、右上角显示「轮询 N/M · 剩余 N 秒」（首次进入默认全部页面参与）；在轮询播放页**再按一次【菜单】**，控制菜单首项是否为「轮询设置」；
19. **轮询设置**：进入「轮询设置」后把间隔改为 10 秒、移出 1 个页面、按【左/右】调整顺序；按【返回】确认回到**轮询播放**（不是首页）且新设置立刻生效；「开机自动播放」开启后重启应用，确认自动进入轮询；关闭后重启确认停在首页、但【菜单】→「轮询展示」仍可手动进入；
20. **分区展示（进入即配置）**：按【菜单】→「分区展示（2×2 拼接）」直接进页面；方向键是否能在 2×2 之间移动当前分区（含未配置的格）且**目标格亮一下就消失**（不留常驻边框）、移动时四格画面**不应闪断重载**、按【确定】是否弹层可选页面（含「不使用」）；选好后该格是否立即加载、其余格不受影响；按【菜单】是否弹出「刷新全部页面 / 返回首页」；确认**没有**独立的"分区设置"界面；
21. 逐个进入大屏：页面是否铺满屏幕（无黑边、无裁切），需登录的大屏是否自动完成登录；
22. 在大屏页按方向键，焦点是否在按钮/页签等可交互元素间移动，按确定是否触发对应操作；按【菜单】可刷新与缩放；
23. 在首页按【返回】，确认弹出退出确认框且默认焦点在【取消】；
24. **设置是否持久化**：设置好轮询与分区后，用 `adb shell am force-stop com.digitalcenter.tvshow` 杀掉进程再打开，确认设置仍在（存于本机 SharedPreferences）；
25. **长时间运行**：分区展示连续跑 30 分钟以上，观察是否卡顿、掉线或 WebView 被回收（4 个 WebView 同时运行对性能有要求，必要时减少同时配置的格位）。

### 多设备互控（1.8 装包 / 打开后确认）

26. 平板打开 `/console`（独立控制台；也可从显示端首页顶栏「设备控制」按钮进入）：全场设备（电脑 / 平板显示端 / 电视）是否都已出现、在线点是否为绿；电视默认名「新设备-xxxx」可点按改名；**控制台自身不出现在列表里**；
27. 只勾选一台电视 →「显示页面」选某页 → 电视 **≤3 秒**切换并出现「远程被控」角标；按遥控器方向键应只弹 Toast「远程被控中」；
28. 电视按【菜单】：菜单是否只剩「控制模式」与「关闭」两项；选「控制模式」→ 确认框默认焦点在「继续受控」；确认退出后**画面保持**、按键立即恢复，控制台上该卡片 ≤3 秒变「本地控制」；
29. 再对该电视下发任意展示指令 → 电视自动切回被控（开关不构成否决权）；
30. 逐台各显不同画面：只勾「一号电视」选画面1 → 只勾「二号电视」选画面2 → 只勾某电脑选画面3，三台各自生效互不影响；
31. 对一台电脑显示端下发 `show`：页面切换后**鼠标依旧可点**（点卡片、点顶栏按钮都正常）——电脑 / 平板显示端永不锁定；
32. 「轮询…」下发（多屏同步切换默认不勾）：电视进入轮询、右上角有进度指示；勾选「多屏同步切换」后多台翻页时机一致；
33. 「存为场景」→ 命名；改动几台设备画面后点「▶ 场景名」→ 全场 ≤3 秒恢复该场景（离线设备显示"待送达"，恢复后自动补上）；
34. **受控电视断电重启**：重启后自动回到设定画面（受控 + 开机恢复开）；「开机恢复」在控制台卡片上可逐台关闭；
35. **受控电视拔网线**：画面继续、锁定与角标保持；恢复网线后控制台在线点变绿、心跳续上。
