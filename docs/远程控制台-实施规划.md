## 一、最终形态（目标快照）

- 平板/电脑浏览器打开 `http://<服务器>:18080/`（或书签 `/console`）即拥有**控制权**：对全馆设备（3 电脑 + 2 电视 + 平板自身）单台/多台/全部下发——显示某页、轮询、2×2 分屏、回首页、刷新、强制同步；
- **场景预设**一键切换全馆现场（晨会/来访/值守），支持"存为场景"；
- 每台设备（含平板）有**「本地控制 / 远程被控」开关**：Web 在顶栏、电视在【菜单】首项；初次进入默认本地控制；控制端**任何展示指令自动接管**（强制切换 + 锁定展示操作 + 角标）；现场人员经**二次确认**即可交还本地；再次下发自动切回；
- 指令 3 秒内送达，存储转发（设备离线也能收到）；设备断电/浏览器重开自动恢复设定画面（远程被控态）；
- 电脑/平板**免安装**（重建 `index.html` 即生效）；电视出 **1.8 APK**；
- 全程零新依赖、零新端口、内容通道零改动。

## 二、冻结的设计决策（实施依据，不再讨论）

| # | 决策 | 来源 |
| --- | --- | --- |
| 1 | 设备三类：电脑/平板 = Web 客户端（可控可被控）；电视 = APK（仅被控）；服务端不区分角色 | v2 |
| 2 | 控制能力内置 Web 客户端（「设备控制」screen）；`/console` 为直达别名（客户端页 + `?screen=control`） | v2 |
| 3 | 受控体系无退网开关：指令永远自动接管，设备无法拒绝、永远在体系内 | v3/v4 |
| 4 | 模式开关：Web 顶栏胶囊、电视【菜单】首项；初次进入默认本地控制；交还后画面保持 | v4 |
| 5 | **退出远程被控一律二次确认**（设备端开关、电视菜单、控制端「取消控制」三个入口）；进入远程与下发指令不需确认 | 评审决议 |
| 6 | 开关实现 = 服务端权威 `managed` + 设备即时影子 `localMode` + 心跳捎带一次性意图 `switchTo`（未确认前重发，幂等）；冲突按到达顺序收敛，指令覆盖开关意图 | v4 |
| 7 | 指令集：`show`/`rotate`/`zone`/`home`（展示类，自动接管）+ `refresh`/`sync`（维护类，不改模式）；`desired` 只存展示类；「取消控制」= `POST /api/ctl/release`（`managed=false` + desired 清空），不是指令 | v3/v4 |
| 8 | 存储转发；`desired` 覆盖不排队；`seq` 全局自增、最后写入者胜 | v2/v3 |
| 9 | `bootRestore` 仅远程被控态生效；`tv`/`pc` 默认开、`tablet` 默认关，注册时定一次、逐台可改 | v3/v4 |
| 10 | 轮询同相切换 `phaseSync` **默认关** | v3 |
| 11 | 场景预设：按设备 `steps`；保存当前现场（desired/reported → 等价指令）/一键应用/重命名/删除 | v3 |
| 12 | 传输 = 3 秒短轮询心跳（心跳+领指令+回状态+模式同步四合一）；长轮询留作升级路径（`?hold=1`） | v2/v4 |
| 13 | 设备身份 deviceId 与 IP 解耦（浏览器/APK 本地生成终身不变）；部署约定每台电脑固定访问地址（origin 稳定） | v3 |
| 14 | 工程约束：服务端零依赖（Node 内置模块）单端口 18080；Web 无框架单文件；APK 不引第三方库；对老客户端完全向后兼容 | v2 |

### 6.2 `test-ctl.mjs` 用例清单（P1 门禁）

1. 首次心跳建档（默认名、kind 自报、bootRestore 默认值按 kind：tv/pc 开、tablet 关）；
2. 重复心跳注册幂等；
3. 无 desired 时响应 `desired:null`（无操作不重发）；
4. 下发 → 下一拍领取 → ack 闭环；
5. 同一指令重复领取幂等（结果不变）；
6. `boot:true` 且 `managed` 且 `bootRestore` → 无条件重发；
7. 本地控制态 `boot:true` 不重发；
8. `switchTo:"local"` → `managed=false` + desired 清空；
9. `switchTo:"remote"` → `managed=true`；
10. `switchTo` 未确认前重发无重复副作用（幂等）；
11. 展示类指令把 `managed` 置 true 并清除未送达的本地交还意图；
12. `release` → `managed=false` + desired 清空；
13. 对离线设备 send → 档案已更新、`lastSeen` 不变（存储转发）；
14. `targets:["*"]` 命中全部设备；
15. 校验 400 组：未知 cmd / 未知 entryId / `zone.slots` ≠4 / interval 越界 / 空 targets；
16. `seq` 全局自增，多控制端并发最后写入者胜；
17. devices 列表：reported / lastSeen / 在线三档判定 / 待送达标记；
18. 改名 PUT 生效；
19. 删除设备 → 下次心跳重新注册；
20. scenes 保存 / 更新 / 删除 + 校验 400；
21. `/api/admin/health` 含 `ctl` 字段；
22. `/console` 别名返回客户端页（与 `/` 同内容）。

### 6.3 `test-ctl-ui.mjs` 用例清单（P2–P4 门禁）

**受控侧（P2）**：
1. 打开首页即注册，出现在 `/api/ctl/devices`（kind 正确）；
2. 下发 `show` → 3s 内切 display screen 并加载对应页；
3. 下发 `rotate` → 写 localStorage rotation 段 + 进入轮询；
4. 下发 `zone` → 进入分屏且四格正确；
5. 下发 `home` → 回首页；
6. 被控后：顶栏导航禁用、iframe 不可点、开关显示"远程被控"、角标出现；
7. 点开关 → 二次确认弹层 → 确认 → **本机立即解锁**（不等服务端），心跳后服务端 `managed=false`；
8. 确认弹层点取消 → 保持被控；
9. 再次下发指令 → 自动切回被控（含角标与锁定恢复）；
10. 刷新页面 → boot 恢复（被控 + bootRestore 时自动回到设定画面）；
11. 断网（拦截 beat）→ 拨开关 → 意图暂存；恢复网络 → 意图送达、服务端翻转；
12. `refresh`/`sync` 不改变模式。

**控制侧（P3）**：
13. 设备列表渲染（含本机标记、模式、在线点、状态摘要）；
14. 单台下发（只勾一台，其余不受影响）；
15. 群组下发（勾选多台/「*」）；
16. 「取消控制」需确认，确认后设备转本地；
17. 点按改名并持久化；
18. 轮询弹层：phaseSync 默认不勾、间隔预设与调序可用；
19. 分屏弹层四格可配"不使用"；
20. 操作后列表即时刷新。

**场景（P4）**：
21. 「存为场景」捕获被控设备 desired 与本地设备 reported 转换；
22. 「应用场景」逐台下发，被控设备自动接管，进度显示 x/y；
23. 含离线设备的场景 → 补投递标记"待送达"；
24. 场景重命名/删除；
25. 引用已删设备的 step 跳过并提示。

### 6.4 电视端验证（P5 门禁 + 部署自检）

编译产物核对（aapt2/apksigner）+ JVM 单测。**部署自检清单新增条目**（现场执行，写入 README）：

1. 电视启动后出现在控制 screen 列表（kind=tv、默认名可改）；
2. 平板下发 `show` → 电视 ≤3s 切换并被控（角标、按键锁定、【菜单】可开且首项为控制模式）；
3. 电视【菜单】→ 切换本地 → 二次确认（默认焦点"继续受控"）→ 立即解锁、画面保持，平板上状态变"本地控制"；
4. 平板再下发 → 电视自动切回被控；
5. 轮询下发 → 电视进入轮询、右上有进度指示；`zone` 下发 → 四格正确；
6. 断电视电源重启 → 自动回到设定画面（被控 + bootRestore）；
7. 拔网线 → 画面继续、锁角标保持；恢复网络 → 心跳自动续上；
8. 场景一键应用 → 5 台同时切换，进度正确。

## 八、风险与回退

| 风险 | 对策 |
| --- | --- |
| 服务端改动影响既有功能 | ctl 模块与路由**纯增量**；每个门禁重跑全部既有测试脚本；`/api/config` 等内容通道零改动 |
| 需要回退 | 服务端摘除 ctl 路由即回到现状；已升级客户端 beat 得 404 后静默退避，无副作用；devices.json 独立于 config.json，互不影响 |
| 老 APK 混跑 | 老客户端不发 beat，仅不出现在列表，其余行为不变；无强制升级依赖 |
| 指令/开关 3s 竞态窗口 | 已在设计 §8.3 定死收敛规则（先应用指令、再执行交还意图），两端最终一致 |
| 被控电脑换访问地址 → origin 变 → 重复注册 | 部署约定固定地址 + 书签锁定；旧条目列表删除即可 |
| phaseSync 时钟差 | 默认关；仅勾选时依赖内网 NTP |
| 设备规模增长 | 7 台 ≈ 2.5 req/s；长轮询 `?hold=1` 为预留升级路径，接口形状不变 |

## 九、执行约定

1. **顺序推进 P0 → P6**，每阶段通过验证门禁后才进入下一阶段；阶段完成时在会话中给出验证证据（测试输出摘要、产物核对结果）；
2. 服务端测试一律经 `node server/test-run.mjs` 隔离实例（独立端口 + 临时数据目录），禁止直打生产数据；
3. 不引入任何新 npm 依赖，服务端仅用 Node 内置模块；Android 不引第三方库；
4. 内容通道（`/api/config`、`ConfigRepository`、缓存结构、`CACHE_SCHEMA`）零改动；
5. 实施前先 `git init` 提交基线（当前目录未纳入版本管理），每阶段完成做一次提交，便于回退与审阅；
6. UI 文案统一用词：「本地控制」「远程被控」「取消控制」「设备控制」「场景」——与设计文档、README 保持一致。
