## 优化内容摘要

- **稳定性（阶段 1）**：SIGTERM 优雅退出（先停采集/转码再关 HTTP）；413 先回可读 JSON 再断连；日志轮转 `logrotate`；极速会话目录 0700 / 状态文件 0600。
- **性能（阶段 2）**：本机设置内存缓存；控制台按卡增量刷新且页面隐藏时暂停轮询；首页宫格增量重绑；MJPEG 帧合并丢弃；注入脚本缓存。
- **体验（阶段 3）**：设置页焦点保持、首页空态面板、分区错误重试、被控文案分场景、后台暂停轮询、展示页/分区配置时效、控制台搜索筛选、管理后台自定义确认弹层。
- **结构与可维护性（阶段 4）**：`server.js` 拆为 `http-util` / `store` / `routes`；展示类 WebView 收敛到 `WebViewFactory`；缓存序列化收敛到 `ConfigJson`；README 拆为四篇文档；admin/console 改为模板构建并复用公共片段；Kotlin 单测 17 项；CI 与 `check.sh` 收口。
- **发布准备（阶段 5）**：数据文件权限统一 0600（写入逻辑持久保持）；旧端口注释清理；全量回归 + 线上冒烟 + 构建可复现校验；浏览器端关闭标签页不再弹原生「离开此网站」确认；平板触屏视口下顶栏不再被误判为全屏而隐藏。

### 2026-11-03 补充修复（现场反馈）

- **控制台重命名弹层**：取消「点击遮罩关闭」，平板软键盘弹出导致的可视区域变化不会再误关输入框；仅保留「取消 / 关闭 / Esc」退出。
- **远程极速模式开关**：控制台设备卡按各设备心跳上报的 `turbo` 状态取反下发 `turbo` 指令（服务端归为维护类，不改变受控模式）；电视端 / 网页端应用后按新地址重载当前画面，分区页四格全部重载。
- **极速状态回流修复**：控制台设备卡增量刷新签名补上 `reported.turbo`。此前设备本机切换极速后卡片不重建，控制台一直显示旧状态，且按钮点击取反也基于旧值，造成「上报 / 下发不生效」。
- **控制台新增「首页」入口**：每台设备的显示页面下拉与底部勾选设备下拉均常驻「首页」，可一键让对端回首页（原有「回首页」按钮保留）。
- **控制台设备删除（临时移除）**：设备卡新增「删除」，仅从控制列表暂时移除档案；设备下一次心跳（≤3 秒）会自动重新注册出现，便于现场清理暂时离线的旧设备（不会永久屏蔽任何设备）。
- **控制台卡片信息与类型**：状态顺序固定为「在线/离线 → 本地/远程控制 → 版本 → IP」，在线绿色、离线黄色、本地控制绿色、远程控制蓝色，不再显示「暂无上报」；点击类型标签可在 PC → PAD → TV 间循环切换，手动设置优先于客户端心跳上报。
- **管理后台与远程控制台弹窗关闭逻辑**：所有弹窗取消「点击遮罩关闭」，只能通过「保存 / 确定 / 取消 / 关闭」按钮退出（Esc 等同取消）；安卓端确认框已禁用外部触摸关闭，仅保留「确定 / 取消」。

### 2026-11-04 补充修复（现场反馈）

- **下发后即时变「远程控制」**：控制台下发展示类指令成功后立即本地重绘（与服务端 `managed=true` 语义一致），不再等待 3 秒轮询；同时修复「卡片下拉获得焦点时整个设备列表暂停重渲染」的旧逻辑，现在只暂缓重建当前聚焦的那张卡，失焦后立刻补齐。此前必须先手动点「刷新」才能看到本地控制 → 远程控制的变化。
- **设备身份只认 `tvshow.deviceId`（localStorage）**：撤销「相同 IP 自动归并」。同一来源 IP 的不同 deviceId 各自成行，避免路由器 NAT 后整片 192 网段设备被误合并成一台。
- **为什么不用 MAC**：HTTP 服务端只能拿到三层来源 IP，拿不到客户端 MAC；MAC 只在同一广播域可见——本机实测 `10.8.32.27` 已经 `via 10.8.11.253` 路由，服务端 ARP 里只有网关 MAC，按 MAC 归并会把该网关下所有设备并成一台。浏览器也不向 JS 暴露 MAC；Android 10+ 默认随机化 MAC，`getMacAddress()` 无系统权限时返回占位值，不能作为稳定身份。
- **重复行的处理**：同一台电脑开两个浏览器会各占一行（各自独立的 deviceId），这是预期行为。多余的浏览器关闭后，在控制台点「删除」即可移除档案；删除是临时移除，该浏览器若仍在线并继续心跳，≤3 秒会重新出现。

### 2026-11-10 补充修复（现场反馈）

- **页面更新后电视端自动生效**（原来必须手动刷新或重启）：
  - 管理后台改了页面配置（地址 / 缩放 / 自动适配 / 兼容转译 / 极速参数 / 自动登录）：电视展示页每 2 秒对齐一次配置快照，当前入口字段变化即按新配置重载；其他页面变化不触发重载。分区展示逐格比较，只重建变化的那格。
  - 目标网页本身重新制作发布（URL 不变）：服务端每 30 秒探测入口页面的 `ETag` / `Last-Modified`，无校验头时退回「正文前 64KB 哈希 + 连续两轮一致才确认」（避免实时数据页被误判）；指纹变化经心跳 `content.pages` 下发，电视端与分区页自动重载当前页；极速模式的常驻截图页由服务端同步重载。
  - 探测周期用 `TVSHOW_PAGE_WATCH_SEC` 调整（最小 5 秒，0 = 关闭）；自签名 HTTPS 入口沿用「忽略证书错误」配置。
- **注意**：以上电视端改动需重新打包安装 APK 后生效；服务端已上线，电脑端与电视端心跳协议保持兼容。

### 2026-11-10 现场修复（旧内核白屏）

- **现象**：电视端（WebView Chrome/66）非极速模式打开「物探中心网络监控系统」提示 `页面无法显示`，脚本错误为 `Uncaught SyntaxError: Unexpected token ?`；极速模式正常（服务端 Chromium 内核较新）。
- **原因**：该页重新部署为 Vite 现代构建，产物含 `??` / `?.`（需 Chrome 80），Chrome/66 解析即失败。
- **处理**：为 `entry-697309`（物探中心网络监控系统）打开「旧内核兼容转译」，代理把 JS 降级到 `chrome66` 并注入运行时垫片，实测大屏完整渲染（登录页 `/api/admin/me` 401 属正常）；同时为含同类语法的 `security-cockpit`（物探中心网络安全监控与自动化运维平台）打开该开关。已装 v2.1 APK 的电视会在 ≤5 秒内自动按代理地址重载，无需重装或手动刷新。
- **运维提醒**：目标大屏重新部署为现代构建后若再次白屏，先看提示层里的脚本错误；出现 `Unexpected token ?` / 类字段报错，在管理后台为该入口勾选「旧内核兼容转译」即可（需服务器已安装 `esbuild`）。

## 回滚方案

- **服务端代码**：切回上一发布 commit 后 `systemctl restart tvshow`（不要使用会丢弃现场数据的强制清理命令）。
- **数据**：用备份目录中的 `config.json` / `devices.json` 覆盖 `server/data/` 对应文件，重启服务。
- **APK**：小米电视覆盖安装要求 versionCode 严格递增，**已升级的高版本无法降级覆盖**；回滚需卸载后安装旧包，现场需评估。

## 已知限制与遗留项

- **实机 UI 未验证**：APK 已打包并通过签名校验，但开发环境无 KVM 硬件加速，电视端界面与遥控器交互需按[部署自检清单](部署与运维.md)在真机确认。
- **凭据轮换（A3）**：`keystore/` 与 `gradle.properties` 的默认口令仍为交付示例值，正式外发前应替换。
- **同一台电脑的多个浏览器各占一行**：设备身份以浏览器 `localStorage` 的 `tvshow.deviceId` 为准，不做 IP/MAC 归并。多余浏览器关闭后在控制台「删除」即可；若该浏览器仍在线，会按原规则在下次心跳重新出现。
- **可选依赖**：旧内核兼容转译需 `esbuild`；极速模式需 `playwright-core` + Chromium；摄像头取流依赖现场网络与 ffmpeg。
- **同源风险**：管理接口内网免鉴权，务必用防火墙限制 `18000` 访问范围（见[排障与验证](排障与验证.md)）。
