# 排障与验证

> 现场注意事项（客户端与页面）与历史验证记录。
> 文档索引：[README](../README.md)

## 注意事项（客户端与页面）

1. **必须使用 `http` 或可信证书的 `https`**：内网自签名证书请将该入口的 `allowInsecureSsl` 置为 `true`，否则会停在证书错误页。生产环境更建议为内网大屏配置受信任证书。
2. **首次访问与 Cookie**：自动登录依赖页面的正常登录流程，登录态由页面自身的 Cookie / localStorage 保存。若大屏系统本身不支持长期登录态，每次进入大屏页面都会自动重新登录一次，属正常现象。
3. **签名口令**：正式交付前建议修改 `gradle.properties` 与 `keystore/` 中的默认口令，或替换为贵方自有证书。
4. **WebView 内核版本（电视端白屏的头号原因）**：电视机的网页渲染能力由**系统自带的「Android System WebView」内核版本**决定，与电视机型年份强相关（本应用走系统 WebView，无法自带内核）。老电视（如小米电视 Android 6.0.1 / MIUI TV 1.3.127）的内核通常被夹在 **Chrome 57~71**，而现代大屏前端会用到更高版本才支持的语法：
   - `??`（空值合并，需 **Chrome 80**）、类字段 `class A { x = 1 }`（需 **72**）属于**硬语法错误**，解析即失败 → **整页白屏，polyfill 无法补救**；
   - `.at()`（92）、`replaceAll()`（85）、`Promise.allSettled`（76）等属运行时 API，可 polyfill（服务端在开启兼容转译时会自动补，见下）。

   **如何现场确认内核版本**：在大屏页按【菜单】，信息浮层右上角会显示 `内核 Chrome/xx`。**xx < 80 出现白屏基本可确定是内核问题**（例：虚拟化集群页需 ≥72、AI 大模型页需 ≥80）。

   **无内容 / 天白屏时的兜底**：应用会在页面加载后连续两轮探测可视内容，若仍判定为空白，则用「页面无法显示」提示层替代白板，屏幕提示 `菜单 刷新重试 · 返回 退出`，不再让现场只看到一片白。

   > 现场案例（2026-11-10）：电视端（Chrome/66）打开「物探中心网络监控系统」提示
   > `Uncaught SyntaxError: Unexpected token ?`（`10.8.14.200/assets/index-*.js`），
   > 极速模式正常（服务端 Chromium 内核较新）。原因是该页重新部署为 Vite 现代构建，
   > 产物含 `??` / `?.`。已为该入口打开「旧内核兼容转译」，代理把它降级到 `chrome66`
   > 并注入垫片，实测大屏可正常渲染；同时顺手为含同类语法的「物探中心网络安全监控与
   > 自动化运维平台」打开了该开关。开启后配置版本自动下发，已装 v2.1 APK 的电视
   > **≤5 秒自动按代理地址重载**，无需重装或手动刷新。

   **处理路径**（按可行性排序）：
   1. **在管理后台为该入口勾选「旧内核兼容转译」**（推荐）——服务端代理把该页 JS 降级到 `chrome66` 并注入运行时垫片，无需改目标系统、无需重装 APK；前提是服务器装过 `esbuild` 且该入口走**代理模式**，详见《架构与实现》的「电脑浏览器客户端 → 旧内核兼容转译」；
   2. 在电视上打开 **Google Play / 应用商店 → 搜索「Android System WebView」（或「Chrome」）→ 更新到最新版**（最省事，但部分老机型商店里没有该应用）；
   3. 通过 `adb install -r` 侧载较新的 WebView APK（需与系统签名兼容，风险较高，可能无法安装）；
   4. **让目标大屏系统提供兼容构建**（关掉 `??` / 类字段、降低构建 target），从源头根治（需要对方团队配合）；
   5. 若该入口不要求嵌入，可在管理后台为其勾选「强制原址打开」，改为在系统浏览器中打开（浏览器内核往往比系统 WebView 新）。
5. **缩放调整建议**：先看默认效果。若页面留有黑边或内容偏小，优先调整该入口的 `scale`（如 90 / 110）；若页面明显被裁切，确认 `autoFit` 为 `true`。临时调整可在页面内按【菜单】→ 放大/缩小（不写回服务端）。
6. **页面自身声明了固定 viewport 宽度**：若页面在 `<meta name="viewport">` 中写了固定的 `width`（而非 `device-width`），会覆盖 WebView 给出的 1920×1080 视口，此时用该入口的 `scale` / `autoFit` 调整，或把页面 viewport 改为 `width=device-width`。
7. **如何确认电视上的实际视口**：可临时用 Chrome 远程调试（`chrome://inspect`）查看 `window.innerWidth`；1080p 电视上正常应为 1920。启动日志里也会打印「屏幕 …px, densityDpi=… → WebView CSS 视口 …」。
8. **焦点落在图表上**：可点击的图表元素（如 SVG 扇区）会被纳入导航。若某个大屏的图表区域不需要遥控器操作，或页面用假 `cursor:pointer` 标记了整块装饰区域，可在页面中为可交互节点显式添加 `role="button"` 或 `tabindex="0"`（这些会被识别为强交互元素），并避免给纯装饰容器设置 `cursor:pointer`。
9. **引导配置的外部覆盖路径**：外部引导文件放在应用私有目录 `/sdcard/Android/data/com.digitalcenter.tvshow/files/config.json`（Android 10 及以上无需额外授权）；用 `adb push` 前请先启动一次应用，让目录自动创建。
10. **多屏部署**：所有电视共用同一个服务端，改一次内容全部生效；新增/调整入口只需在管理后台操作，无需逐台维护文件。
11. **轮询进入即播，不必先设置**：按【菜单】→「轮询展示」会**立即开始轮播**；这台电视从未选过轮询页面时，默认让服务端全部页面参与（点开即用）。要改设置，在**轮询播放页再按一次【菜单】**→「轮询设置」。其中「开机自动播放」默认关闭，只决定应用启动时是否自动进入轮询；不需要自动播放时保持关闭即可，随时可用【菜单】手动进入。
12. **轮询/分区默认是「各台设备各自配置」的**（服务端不保存展示策略）；**需要"改一次全场生效"时用多设备互控**（见《架构与实现》的「多设备互控」）：控制端对单台 / 多台 / 全部设备下发显示、轮询、分屏或场景，指令写入各设备本机设置并立即生效——这正是指令的实现方式，与本机设置无缝衔接。
13. **分区展示是「进入即配置」**：首页【菜单】→「分区展示（2×2 拼接）」直接进页面，方向键选格、按【确定】为该格选页面，**没有独立的"分区设置"界面**。四格的 WebView 均不可聚焦，因此分区页内网页元素不再响应遥控器方向键（这是为现场选格让路的取舍），页内自动登录与脚本注入仍照常运行。另外四格**始终按 1920×1080 的分区视口渲染**（客户端按每格物理宽度重写 WebView 密度）：在 3840×2160 的拼接屏上每格正好 1920×1080，1:1 无损；在普通 1920×1080 电视上每格只有 960×540 物理像素，页面会被整体等比缩小到 50%（布局不变、只是变小，字会很小）。若要在大屏上 1:1 呈现，请使用 4 块 1920×1080 拼接的 3840×2160 屏幕。
14. **四个 WebView 同时运行有性能开销**：分区展示会同时加载最多 4 个大屏页面，低配电视可能出现卡顿、内存紧张甚至 WebView 被系统回收。建议：只给确实需要同时展示的格位选择页面（未选择的格位不创建 WebView），另外三个分区尽量选轻量页面，并在真机上确认长时间运行的稳定性。轮询播放是单 WebView 逐页切换，开销与普通大屏页一致。
