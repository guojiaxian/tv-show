# 素材上墙 · 类型分析与实现设计

> 需求：远程控制台对某台（或勾选多台）设备下发「素材上墙」，从本地选择素材（图片、PDF、PPT 等）上传后**立刻在大屏上展示**；要求先分析可行素材类型，Web 与 TV 都要支持，PPT 需要可播放，实现后做完整功能与性能测试。
> 索引：[README](../README.md) · [API](API.md) · [部署与运维](部署与运维.md)

## 一、素材类型可行性分析（要求 1）

约束回顾：**电视端 WebView 为 Chrome 66**（不能引第三方渲染库），服务端沿用「零依赖 + 可选增强」惯例（esbuild / playwright-core 先例）。显示端消费素材的唯一可行通用形态是「**服务端把素材变成 Chrome 66 能直接渲染的东西，再由两端加载同一个 URL**」——与 `/shot/<id>/view`（极速模式包装页）、`/cam/view`（画面墙网页）同构。

| 素材类型 | 电视端 Chrome 66 原生可渲染？ | 结论 | 实现路径 |
| --- | --- | --- | --- |
| 图片 JPG / PNG / GIF（含动图）/ WebP / BMP / SVG | ✅ `<img>` 原生支持 | **支持** | 原样存储，播放页 `<img>` 全屏 contain 展示，无需转换 |
| **PDF** | ❌ Android WebView **没有内置 PDF 渲染器**（桌面浏览器 iframe 直嵌可行，但电视端必然空白，两端不一致） | **支持（服务端转图片）** | `pdftoppm -png`（poppler-utils，可选系统依赖）把每页转成 PNG → 分页播放页 |
| **PPT / PPTX** | ❌ 任何浏览器都不能原生渲染 | **支持（可播放）** | LibreOffice `soffice --headless --convert-to pdf` → 走 PDF 管线 → 分页图片 + **定时翻页自动播放**（间隔可配、循环、页码指示） |
| DOC / DOCX | ❌ | **支持（同一管线）** | 与 PPT 共用 soffice → PDF → 图片链路，转出来是静态文档页 |
| 视频 MP4（H.264）/ WebM | ✅ `<video>` 原生支持（Chrome 66 硬解 H.264） | **支持** | 原样存储，播放页 `<video autoplay muted loop>`；服务端支持 Range 请求（拖动/起播必需） |
| XLS / XLSX | — | **不支持** | 表格转图片版式极差，大屏不可读；需要时先在源端导出 PDF |
| HLS / RTSP 视频流 | ❌（HLS 需 hls.js、RTSP 无解） | **不支持** | 摄像头画面请用既有的 `type=camera` 画面墙 |
| Office 在线嵌入 / 外部网页 | — | **不支持** | 属「普通页面」，用既有入口 + 互控 `show` 指令即可 |

**依赖降级矩阵（沿用 esbuild / playwright-core 的可选依赖惯例）**：

| 服务器装有 | 图片 | 视频 | PDF | PPT/DOC |
| --- | --- | --- | --- | --- |
| 无任何额外工具 | ✅ | ✅ | ❌ 上传即提示「未安装 poppler-utils」 | ❌ 提示「需要 LibreOffice」 |
| + poppler-utils（`yum install -y poppler-utils`） | ✅ | ✅ | ✅ | ❌ |
| + LibreOffice（`yum install -y libreoffice-headless`） | ✅ | ✅ | ✅ | ✅ |

工具缺失**不影响上传**：文件照常入库，素材状态为「不可用」并附原因，控制台明确提示；装好工具后删除重传即可，服务端**照常启动、无需改代码**。

## 二、总体设计

```
控制台 /console                     服务端 18000                       显示端（Web / 与 TV APK 同规则）
┌──────────────────┐   ①POST /api/media/upload（原始字节流）  ┌──────────────────────┐
│ 设备卡「素材上墙」 │ ──────────────────────────────────────▶ │ server/media.js       │
│ 群组「素材上墙」   │   ②轮询 /api/media（processing→ready）   │  data/media/ 存储      │
│   选择文件→上传    │ ◀────────────────────────────────────── │  PDF:  pdftoppm→PNG×N │
│   就绪后自动下发   │   ③POST /api/ctl/send {cmd:"media"}     │  PPT/DOC: soffice→PDF │
└──────────────────┘ ──────────────────────────────────────▶ └──────────┬───────────┘
                                                                     │ ④心跳领取 media 指令
                                          GET /media/<id>/view?interval=10 ◀── 两端加载同一播放页
                                          GET /media/<id>/raw /page-N.png  ◀── （图片/视频/分页图片）
```

- **指令层**：互控通道新增展示类指令 `media`（args：`mediaId` 必填、`intervalSec` 可选 3–3600 默认 10）。展示类 = 自动接管（managed=true）、desired 覆盖不排队、回归即本地控制、场景可入——与 show/rotate/zone/home 完全同语义；下发时校验 mediaId 存在，离线设备照常拦截。
- **播放页（两端唯一入口）**：`GET /media/<id>/view?interval=N`，**ES5 编写**（Chrome 66 底线）：
  - 图片：全屏 `<img>`（object-fit: contain，黑底不变形；GIF 动图原生播放）；
  - PDF/PPT/DOC：双缓冲分页播放器——预加载下一页、按 `interval` 定时翻页、循环播放、左下角页码指示；PPT 的「可播放」即由此实现（服务端已把每页栅格化，翻页只是换图）；
  - 视频：`<video autoplay muted loop playsinline>`；
  - 不可用：展示原因文案（含装哪个工具可解决）。
- **身份与状态**：电视端新增 `MediaDisplayActivity`（复用 `WebViewFactory` 1920×1080 视口装配），上报 `mode:"media"` + mediaId；电脑端复用展示屏内嵌播放页，上报同一状态。控制台设备卡摘要显示「素材：名称」，本地操作偏离（回首页/换页）照常自动交还本地。
- **存储**：`server/data/media/`（原始文件 + 转换产物，0600/0700）+ `server/data/media.json`（注册表，原子写 + .bak，均不入库 .gitignore）。
- **上传**：`POST /api/media/upload?name=<文件名>`，请求体为**原始文件字节**（不做 multipart 解析，零依赖）；上限 200MB，超限 413。转换（PDF/PPT）异步进行，注册表状态 `processing → ready | unsupported`；控制台上传后轮询状态，**就绪即自动向目标设备下发**，满足「上传后立刻上屏」。

## 三、验证方案（要求 4 的落点）

| 层 | 验证 | 位置 |
| --- | --- | --- |
| 服务端功能 | 上传/列表/删除/越权/超限 413/类型 400；图片原样回源；PDF 转 2 页（测试内嵌最小合法 PDF 生成器）；PPT 无 soffice 时降级原因；播放页 ES5 断言（无 `??`/`?.`）与按 kind 注入；Range 请求 206；素材状态健康检查 | `server/test-media.mjs` |
| 端到端 UI | 控制台真实上传（Playwright setInputFiles）→ 自动下发 → 电脑显示端 iframe 切到播放页 → 服务端 reported.mode=media → 卡片摘要「素材：…」→ 本地脱离自动交还 | `server/test-media-ui.mjs` |
| 性能 | 20MB 上传吞吐（流式直写，RSS 增长 < 40MB）；60MB 大文件内存稳定性；24 路并发拉取分页图片 p95 延迟；播放页首帧时间与自动翻页计时 | `test-media.mjs`（性能段）+ `test-media-ui.mjs` |
| 电视端 | Kotlin 单测（media 指令映射 / 未知指令不锁定）+ 编译 + lint + 签名打包；真机遥控器交互按惯例现场确认 | `CommandApplierTest` + Gradle |

> 本机具备 pdftoppm（PDF 全链路可实测）；无 soffice，PPT 仅能实测「降级提示」分支——工具装上后同一测试自动升级为全链路断言（脚本按可用性自适应）。
