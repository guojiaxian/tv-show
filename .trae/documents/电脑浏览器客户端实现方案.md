# 电脑浏览器客户端 实现方案

## 一、背景与目标

现有系统是「Kotlin Android 电视端 + 零依赖 Node.js 服务端」：电视端负责首页宫格聚合、WebView 加载大屏、轮询展示、2×2 分区展示，服务端（`server/server.js`，默认 18000）是内容唯一数据源。

现在需要在**同一个 18000 服务**上新增一个**正式交付的电脑浏览器客户端网页应用**，完整复刻电视端的操作功能，**去掉遥控器相关操作**，改为鼠标 + 键盘操作，并要求可自动登录、可鼠标点击、界面适配电脑浏览器。

### 已确认的关键决策（来自用户）

| 决策项 | 结论 |
| --- | --- |
| 自动登录 | **混合方案**：默认直连 iframe；对配置了自动登录的入口可切换为「服务端反向代理」使其同源，从而注入脚本自动填表 |
| 界面布局 | **自适应桌面布局 + 全屏演示模式**（不沿用固定 1920×1080 舞台） |
| 轮询 / 分区 | **两者都保留**，改为鼠标 / 键盘操作 |

### 技术前提（决定了方案形态）

浏览器同源策略下，跨域 `iframe` **无法注入脚本**（`auto_login.js` 在 WebView 里由原生注入才可行）。因此「自动登录」只有把目标站代理成同源后才成立——这是本方案必须引入反向代理的唯一原因。鼠标点击跨域 iframe 内部则天然可用。

## 三、服务端：静态托管 + 反向代理

### 3.1 静态托管

在 [server.js](file:///root/tv-show/server/server.js#L455-L465) 现有 `ADMIN_FILE` 分支旁新增 `CLIENT_FILE = path.join(ROOT, 'client', 'index.html')`，`/app` 与 `/client` 返回该文件（`Cache-Control: no-store`，文件缺失时返回 500 并提示）。`/` 仍指向管理后台，不改动既有行为。

客户端页面由 18000 自身托管，因此**接口用同源相对路径 `/api/...`**，不再需要内置 `serverBaseUrl`；仅当以 `file://` 直接打开时才回退到引导配置里的 `serverBaseUrl`（便于本地调试）。

### 3.2 反向代理（`server/proxy.js`）

**路由与映射不变式**

- 路由：`/proxy/<entryId>/<rest...>`，其中 `<entryId>` **只能来自 `data.entries` 的 id**（禁止用 URL 参数指定目标）——这是防 SSRF 的关键。
- 映射：`/proxy/<entryId>` 映射到该入口 URL 的 **origin 根**，`<rest>` 原样镜像。
- 例：入口 `http://10.8.11.3/cockpit` → iframe 打开 `/proxy/security-cockpit/cockpit`；页内根相对 `/api/x` → `/proxy/security-cockpit/api/x` → 上游 `http://10.8.11.3/api/x`。
- **不做路径归一化**：必须使用未剥尾斜杠的原始 `url.pathname`（现有代码里的 `p` 已 `replace(/\/+$/,'')`，会混淆 `/cockpit/` 与 `/cockpit`），代理分支要在归一化之前提前 return。
- **不注入 `<base>`**：路径 1:1 镜像已让相对 URL 天然正确（`/cockpit` 无尾斜杠时上游目录本就是 `/`），注入 `<base>` 会与上游已有 `<base>` 冲突、并破坏锚点与 `pushState` 的相对路径。

**HTML 处理**

- 只对 HTML 做**属性级**改写：把上游绝对源（`http://10.8.11.3`、`//10.8.11.3`）改写为 `/proxy/<entryId>`；把根相对属性（`src="/x"`、`href="/x"`）改写为 `/proxy/<entryId>/x`。跳过 `#`、`//`、`data:`、`javascript:` 等。
- **不对 JS/CSS 做正则文本改写**（会误伤字符串拼接、日期、注释），改为在 HTML 最前注入一段 **shim 脚本**，在运行时 patch：`history.pushState/replaceState`、`fetch`、`XMLHttpRequest.open`、`WebSocket`、`EventSource`，把指向上游源的绝对地址收敛到代理前缀。同时在 shim 里托管 `window.__TV_AUTOLOGIN__` 的读取位（实际注入仍由父页面完成后调用），便于父页面注入 `auto_login.js`。

**响应头处理**

- 剥离阻止被嵌套/审计的头：`X-Frame-Options`、`Content-Security-Policy`、`Content-Security-Policy-Report-Only`、`Cross-Origin-Opener-Policy`、`Cross-Origin-Embedder-Policy`、`Cross-Origin-Resource-Policy`。
- `Location`：不跟随重定向，透传 3xx；相对 `Location` 先按上游请求 URL 解析再加前缀；已带前缀的不重复加（防环）；跨域 `Location` 原样放过（跳出 iframe 属已知限制）。
- `Set-Cookie`：`Path` 做前缀拼接（`Path=/cockpit` → `Path=/proxy/<id>/cockpit`），删除 `Domain`，保留 `HttpOnly/SameSite/Max-Age`；`SameSite=None` 时补 `Secure`。
- 文本响应改写后**必须删除 `Content-Encoding` 与 `Content-Length`**（改分块发送），否则双重解码或截断。
- 请求头：剥离 hop-by-hop（`connection/keep-alive/transfer-encoding/upgrade/proxy-*/te/trailer`），重写 `Host` 为上游 host、`Origin`/`Referer` 为上游源（登录 POST 常校验），透传 `Cookie`、`Content-Type`、`Authorization` 等。

**编码与流式**

- 对上游请求去掉 `Accept-Encoding`，优先拿明文；上游仍压缩时用内置 `zlib`（`gunzipSync` / `inflateSync`→失败回退 `inflateRawSync` / `brotliDecompressSync`）解压后再改写。
- 只对**白名单文本类型**（`text/html`、`text/css`、`application/javascript`、`application/json`、`text/plain`）且体积 ≤ 5MB 的响应做缓冲改写；其余（二进制、大文件、`text/event-stream`）一律流式直通，SSE 不缓冲。
- 请求体流式 `pipe` 到上游，不复用 `readBody`（其上限 256KB）。

**WebSocket**

在 `server.on('upgrade')` 中解析 `/proxy/<entryId>/...`，用 `http.request` 发起带 `Upgrade` 的请求，**必须把 `head` 一并转发**（否则丢首帧）；透传 `Sec-WebSocket-Protocol`；非 101 回 502；`wss` 目标走 `tls.connect`，`rejectUnauthorized` 受 `allowInsecureSsl` 控制。

**生命周期与安全**

- `res.on('close')` 销毁上游请求；上游设置连接/响应超时；每入口并发上限，避免 2×2 + 轮询打满连接池。
- 拒绝自身回环目标（指向 18000 自身的条目）。
- 代理只可能转发到 `data.entries` 里已配置的内网地址，不能当开放代理用。

### 3.3 直连 / 代理策略（不动服务端 schema）

放在**客户端 localStorage 本地偏好**，默认 `auto`：

- `auto`：`entry.autoLogin?.enabled === true` → 走代理，否则直连；
- 展示页工具栏提供「代理 / 直连」二态开关，并把「上次成功模式」记进本地偏好；
- 直连模式下若上游发 `X-Frame-Options`，嵌入会失败且**跨域无法可靠检测**，只做超时启发式提示，引导用户点「用代理方式打开」。

理由：同一份 `/api/config` 由电视端共用，新增字段需要同步 `normalizeData`/`validateEntry`/`fullSnapshot`/管理后台表单与全部服务端测试；而「这台电脑怎么打开」本就是每台机器的差异。

## 四、电脑浏览器客户端（`tools/client-template.html`）

以现有预览页的**视觉语言与协议实现**为蓝本，但重新组织为鼠标优先的正式应用；去掉 `#pcbar` 测试工具栏、虚拟遥控器 `#remote`、固定 1:1 舞台、演示大屏 `mountDemoPage`、注入用 `#codePanel`。**关键：iframe 绝不设 `pointer-events:none`**（预览页有该设置，正式客户端必须保留鼠标点击能力）。

### 4.1 结构

- `#topbar`：品牌区 + 工具区（配置来源标记、立即同步、全屏切换、设置、管理后台链接、退出）
- `#home`：`<h1>` 居中系统标题 + 副标题 + 时钟/日期 + 自适应卡片网格（hover 高亮、点击进入）+ 快捷键提示
- `#display`：顶部工具条（返回 / 标题 / 刷新 / 缩放 − + 重置 / 代理·直连切换 / 新标签打开原址 / 轮询控制）+ iframe 容器 + 加载与失败重试覆盖层 + 左下角信息浮层
- `#zones`：2×2 网格，每格 = 标题栏 + 1920×1080 虚拟视口（`transform: scale()` 适配）+ 未配置占位；鼠标点击格子选页、方向键移动高亮（闪 0.6s 后淡出）
- `#settings`：轮询设置（开关 / 间隔 / 页面勾选与排序）、退出确认开关、清除本地设置、关于
- `#dialog` 通用对话框 + `#toast`

### 4.2 功能对齐表（电视端 → 电脑端）

| 电视端功能 | 电脑端实现 |
| --- | --- |
| 首页宫格 + 标题居中 + 时钟日期 | 同，网格随窗口宽度自适应列数 |
| WebView 单页展示 | `iframe` 展示，保留加载 / 失败 / 重试 / 缩放 / 信息浮层 |
| 控制菜单 | 展示页右上「菜单」按钮 + `M` 键，项同电视端 |
| 返回键回首页 | `Esc` 与「返回」按钮 |
| 轮询展示（进入即播放） | 同；工具栏显示「第 x/n 页 · 每页 Ns」+ 暂停/继续 |
| 轮询设置（开关/间隔/页面与顺序） | 设置面板：勾选参与页面、上下移动排序、间隔下拉（沿用 `INTERVAL_PRESETS`） |
| 时钟推导当前页（多端一致） | 同：本地 `startedAt` + 间隔推导，等价 App 的 `startedAt` |
| 2×2 分区展示（进入即配置） | 同：进入即可选格；每格按 1920×1080 视口渲染 |
| 分区高亮闪一下淡出 | 同：`flashZone` 语义，键盘移动时亮 0.6s 淡出 |
| 单格重建（不重载其它格） | 同：`renderZoneCell` 只重建被改动的格 |
| 增量同步（since/version/epoch/ETag/304、降级全量） | 同协议同端点，逐字对齐现有 `syncFromServer` 行为 |
| 本地缓存 + 离线兜底 + 来源标记 | `localStorage`（键沿用 `tvshow.localSettings`）+ 内置兜底 + 来源 chip |
| 自动登录 | 直连：提示手动登录；代理：同源注入 `auto_login.js` |
| 缩放 / `autoFit` / `scale` | 虚拟 1920×1080 视口 + 等比缩放；`scale` 映射为缩放百分比 |
| `allowInsecureSsl` | 由服务端代理侧 `rejectUnauthorized` 承接；直连由浏览器接管，不做处理 |
| 退出确认（`exitConfirm` / `exitTip`） | 「退出客户端」动作弹确认框；`exitConfirm` 为真时注册 `beforeunload` 原生离开确认（可在设置里关） |
| 遥控器按键映射 | **去掉**（`tv_nav.js` 不引入） |

### 4.3 键盘映射

`方向键` 移动焦点 / 分区选格 · `Enter` 进入确认 · `Esc` 返回上级 · `M` 菜单 · `F` 全屏 · `+` `-` `0` 缩放 · `R` 刷新 · `空格` 轮询暂停/继续。

浏览器限制：iframe 获得焦点后按键不再冒泡到父页面，因此**所有功能都有对应的鼠标按钮**，快捷键仅在焦点未落入内嵌页面时生效——这一点与电视端「分区页 WebView 不可聚焦」的取舍同源，会在界面提示中说明。

### 4.4 本地设置

沿用 App `LocalSettings` 结构（`rotation{enabled,intervalSec,items,startedAt}`、`zones[4]{position,entryId}`），另加 `proxyModes`、`exitGuard`。键名沿用 `tvshow.localSettings`。

## 六、验证

### 6.1 自动化（零依赖）

`node server/test-run.mjs` 增加到 4 个套件。新增 `server/test-proxy.mjs` 自起**假上游** http server（`net` 取空闲端口）并通过管理 API 建入口指向它，覆盖：

- 子路径入口：`GET /proxy/e1/cockpit` → 200；上游收到 `/cockpit`（镜像不变式）
- 请求头：上游收到 `Host=上游`、`Origin` 已改写、无 `connection/keep-alive/accept-encoding`
- 响应头：无 `x-frame-options` / `content-security-policy`；`content-length` 与实际字节一致或走分块；`content-encoding` 已删且 body 可 `JSON.parse`
- 重定向：绝对与相对 `Location` 均带前缀且状态仍 302（不跟随）；跨域 `Location` 原样
- Cookie：`Path` 前缀拼接正确、无 `Domain`、保留 `HttpOnly`/`Max-Age`
- 强制 gzip 的 JS：解压后文本正确、无双重编码
- 304 透传且 body 为空
- WebSocket：假上游 `upgrade` 回 101 并 echo，验证首帧（覆盖 `head` 转发）
- 安全：未知 id → 404；路径穿越被限界；自指向条目被拒
- 流式：SSE 首字节延迟低于阈值，不被整体缓冲

### 6.2 浏览器端到端（临时 Playwright，沿用 `/root/.pwtest` + chromium 既有样板）

- 首页网格渲染、标题为 `h1` 且居中、时钟走动
- 鼠标点击卡片进入展示页；`Esc` 返回首页；`F` 全屏切换
- 展示页缩放按钮改变虚拟视口缩放；失败与重试覆盖层
- 轮询按间隔切换页面；间隔与页面顺序在设置面板可改并持久化
- 分区：方向键移动只更新高亮、不重载其它格；点击某格选页只重建该格
- 代理模式：加载假上游页面 → 自动登录脚本成功填充并提交 → 页面内鼠标可点击
- 全程无 JS 报错（收集 `console` 与 `pageerror`）

## 七、风险与已知限制

1. **同源风险（既有设计遗留）**：被代理页面与 `/api/admin/*`、`/api/config` 同源，理论上可读取配置（含明文口令）。这是「管理后台内网免登录 + `/api/config` 必须下发口令给自动登录」的既有属性，非本次引入；代理侧已限制只能转发到配置内的入口地址，部署侧继续沿用「防火墙限制 18000 访问范围」的缓解办法。
2. **代理兼容性**：目标页若依赖 `location.origin`、硬编码绝对地址、或强校验 `Referer`，仍可能异常；因此保留直连模式作为退路。
3. **直连模式无法自动登录**：跨域限制，只能手动登录一次并依赖浏览器 Cookie 持久化。
4. **键盘快捷键在 iframe 聚焦时失效**：浏览器机制限制，靠鼠标按钮兜底。
5. **真机未验证项**：三个真实内网大屏（`10.8.11.4:1111`、`10.8.12.130`、`10.8.11.3`）本轮无法在环境内连通，需在部署现场按 README 清单确认代理模式下的登录与渲染。
