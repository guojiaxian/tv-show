# 服务端管理系统 + 电视客户端改造方案

## 一、背景与目标

当前 `/root/tv-show` 是一个**纯本地**的电视大屏聚合 App：入口列表与系统标题全部来自包内 `app/src/main/assets/config.json`（或设备外部同名文件），增删页面必须改文件并重新出包、逐台安装。

本次改造为 **C/S 架构**：新增一个服务端管理系统作为**唯一数据源**，电视端退化为**纯展示客户端**——所有页面内容、系统标题、网站地址均从服务器获取，日常增改内容不再需要重新安装 APK。

### 已确认的技术选择（用户决策）

| 决策项 | 选择 | 影响 |
| --- | --- | --- |
| 服务端技术栈 | **零依赖 Node.js**（仅内置模块） | 单文件服务，拷贝即跑，内网离线可部署；本机 Node 22.19 |
| 同步机制 | **启动时拉取 + 手动刷新** | 不做后台定时轮询；本次额外增加「回到前台」触发（见 §7 偏差说明） |
| 管理后台鉴权 | **内网免登录** | 无登录态；需靠网络隔离保障，文档中明确风险 |
| 电视端服务器地址 | **仅打包内置** | 不做电视端设置界面；换地址需重新出包（保留既有外部文件覆盖能力作为运维后门） |

### 与原始需求的偏差（需知悉）

1. 原需求「定期更新 / 实时数据同步」→ 按选择实现为**启动、回到前台、手动（菜单键）**三种触发，**不做**后台定时轮询与 SSE 推送。同步调度器预留 `pollIntervalSec`（默认 `0` = 关闭），设为 `20` 即开启定时轮询，无需改代码。
2. 原需求「数据传输安全性」→ 按选择**不做鉴权**。方案通过「写操作最小化 + 建议防火墙限制来源网段 + 支持入口级 HTTPS」缓解，并在文档中列为部署注意事项。

## 二、总体架构

```
┌──────────────── 服务端（零依赖 Node.js，单进程单端口）────────────────┐
│  server/server.js                                                    │
│   ├── GET  /                      → 管理后台页面（admin/index.html）  │
│   ├── /api/admin/*                → 增删改查 / 标题 / 排序 / epoch     │
│   ├── /api/config?since=<n>       → 客户端增量拉取（304 或 delta）      │
│   ├── /api/config?full=1          → 全量拉取                          │
│   └── /api/version                → 极轻量版本探测                     │
│  server/data/config.json          → 唯一数据源（原子写盘 + 备份）       │
└──────────────────────────────────────────────────────────────────────┘
                    ▲ 管理后台(浏览器)          ▲ 电视客户端(HTTP/JSON)
                    │ 增删改查                  │ 启动/回前台/菜单键 拉取
                    │                           │ 本地缓存 + 版本比对
```

客户端**启动不阻塞于网络**：先用本地缓存（或包内兜底配置）立即渲染首屏，再后台增量同步，有变更才重绘。这样既满足「启动加载时间可控」，也满足「网络不稳定时可用」。

## 三、数据结构与同步协议

### 3.1 服务端数据文件 `server/data/config.json`

```jsonc
{
  "version": 7,            // 全局单调递增版本，每次写操作 +1
  "epoch": 1,              // 「强制全量」代次；管理端可 bump 使所有客户端重拉全量
  "metaRev": 5,            // 系统配置块最后一次变更时的 version
  "prunedBeforeRev": 0,    // tombstones 裁剪水位；客户端 since 低于此值则回退全量

  "appTitle": "数智中心大屏聚合平台",
  "appSubtitle": "DIGITAL CENTER · DISPLAY HUB",
  "exitConfirm": true,
  "exitTip": "按【返回】键将退出应用",

  "entries": [
    {
      "id": "storage-monitor",
      "title": "数智资源中心存储集群资源监控",
      "subtitle": "存储集群容量总览 / 分区视图 / 容量趋势",
      "url": "http://10.8.11.4:1111/",
      "accent": "#2FD2F5",
      "icon": "storage",
      "scale": 0,
      "autoFit": true,
      "allowInsecureSsl": false,
      "autoLogin": { "enabled": true, "username": "show", "password": "...",
                     "usernameSelector": "", "passwordSelector": "",
                     "submitSelector": "", "successSelector": "" },
      "rev": 6             // 本条目最后一次变更时的 version
    }
  ],

  "tombstones": [ { "id": "old-entry", "rev": 7 } ]   // 已删除条目，供增量下发
}
```

字段与客户端现有 `DisplayEntry` / `AutoLoginConfig` **一一对应**（`app/src/main/java/com/digitalcenter/tvshow/config/AppConfig.kt` L10-46），因此 `WebDisplayActivity` 消费入口的逻辑无需改动。

### 3.2 增量协议（满足「避免全量传输」）

`GET /api/config?since=<n>`，同时支持 `If-None-Match: "<epoch>-<version>"`：

| 情况 | 响应 |
| --- | --- |
| `since` 等于当前 version | `304 Not Modified`（空 body，最省流量的启动检查） |
| `since` 可用且服务端留有增量痕迹 | `200` + delta：`{ version, epoch, meta?, upserted[], deletedIds[] }` |
| 首次拉取 / `since < prunedBeforeRev` / epoch 变化 | `200` + `{ full: {...} }` |

delta 中 `meta` 仅在 `metaRev > since` 时下发；`upserted` 为 `rev > since` 的条目；`deletedIds` 为 `rev > since` 的 tombstone。

客户端合并规则：以 `full` 覆盖本地；对 delta 先按 `deletedIds` 删、再按 `upserted` 按 id 覆盖，**保持服务端顺序**；合并后校验 `version` 单调递增，异常则降级为全量重拉（保证一致性）。

## 四、服务端实现（`server/`）

### 目录

```
server/
├── server.js            # 零依赖单文件：路由、CRUD、增量协议、原子写盘
├── admin/index.html     # 管理后台（内联 CSS/JS，无框架、无 CDN）
└── data/config.json     # 运行时数据；首次启动由内置种子（现有 3 个入口）自动生成
```

### API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/config` | 完整配置（后台展示用，含 rev/version/epoch） |
| PUT | `/api/admin/meta` | 修改系统标题/副标题/退出确认等（写 `metaRev`） |
| POST | `/api/admin/entries` | 新建页面（校验 url 必填、id 唯一，自动生成 id） |
| PUT | `/api/admin/entries/:id` | 更新页面（写该条 `rev`） |
| DELETE | `/api/admin/entries/:id` | 删除页面（写 tombstone，`version` +1） |
| POST | `/api/admin/entries/reorder` | 按传入 id 顺序重排（重排序也抬高 version） |
| POST | `/api/admin/epoch/bump` | 强制所有客户端下次重拉全量 |
| GET | `/api/admin/health` | 健康检查（version/epoch/条目数/启动时间） |
| GET | `/api/config?since=&full=` | 客户端拉取（见 §3.2） |
| GET | `/api/version` | 仅 `{version, epoch}` |

### 服务端要点

- **零依赖**：`node:http` / `node:fs` / `node:crypto` / `node:path`，不装任何 npm 包。
- **原子写盘**：写临时文件 → `fs.renameSync` 覆盖 → 保留 `.bak`；进程启动时若主文件损坏则回退 `.bak`。
- **参数校验**：`url` 必填、`id` 唯一且符合 `[a-z0-9-]+`、`accent` 形如 `#RRGGBB`；非法请求返回 `400` + 明确错误信息（后台直接提示）。
- **并发写**：单进程内用「写队列 + 同步落盘」，避免并发请求互相覆盖。
- **端口**：默认 `18080`，可用 `--port` 或 `PORT` 环境变量覆盖（实现时确认端口空闲）。
- **CORS**：对 `/api/*` 返回 `Access-Control-Allow-Origin: *`，便于预览页与后台跨端口调试（内网可接受）。

## 五、管理后台（`server/admin/index.html`）

单文件、无框架、无 CDN，满足「直观的操作界面」：

- **系统标题区**：`appTitle` / `appSubtitle` / `exitConfirm` / `exitTip` 编辑，保存即调用 `PUT /api/admin/meta`，页面即时刷新（满足「标题修改支持实时更新」——后台侧即时生效）。
- **页面列表**：表格展示序号 / 标题 / URL / 图标 / 主题色 / 缩放 / 自动登录；每行「编辑 / 删除 / 上移 / 下移」。
- **新增页面**：表单（标题、描述、URL、主题色、图标下拉、缩放、autoFit、allowInsecureSsl、自动登录账号密码与选择器），提交 `POST /api/admin/entries`。
- **排序**：上移/下移即时调用 reorder，与首页 2×3 宫格顺序一一对应。
- **状态栏**：显示 `version` / `epoch` / 条目数 / 最后更新时间；提供「强制客户端全量刷新」按钮（bump epoch）。
- **操作反馈**：成功/失败 toast，失败显示服务端返回的具体校验错误。

## 六、客户端改造（Android）

### 新增

| 文件 | 职责 |
| --- | --- |
| `net/ConfigClient.kt` | `HttpURLConnection` 发请求（连接 3s / 读取 5s 超时），带 `since` 与 `If-None-Match`，解析 `304` / delta / full；失败重试 2 次（指数退避） |
| `net/ConfigStore.kt` | 本地缓存 `filesDir/server-config.json`：保存合并后的完整配置 + `version` + `epoch` + `etag`；原子写 |
| `net/ConfigRepository.kt` | 单一入口：`snapshot()`（内存 → 缓存文件 → 包内兜底，**同步返回，不阻塞**）、`syncAsync(callback)`（后台线程拉取并合并）、同步状态暴露 |

**不引入任何第三方依赖**：HTTP 用平台自带 `HttpURLConnection`，JSON 沿用 `org.json`，线程用 `ExecutorService` + `Handler`（与现有代码风格一致，`app/build.gradle.kts` 依赖保持 2 条不变）。

### 修改

| 文件 | 改动 |
| --- | --- |
| `config/AppConfig.kt` | `DisplayEntry` / `AutoLoginConfig` **保持不变**；`ConfigLoader` 改为只读**引导配置**（`serverBaseUrl` + 兜底 `fallback`），保留既有优先级：外部文件 → assets。新增 `RemoteConfig`（含 version/epoch） |
| `assets/config.json` | 精简为引导文件：`serverBaseUrl`、`sync.timeoutMs`、`sync.pollIntervalSec`（默认 0）、`fallback`（现有 3 个入口，保证首次安装/服务器不可用仍可显示） |
| `ui/MainActivity.kt` | 启动：立即用 `snapshot()` 渲染 → 触发一次同步 → 有变更重绘；`onResume` 触发同步（受节流，避免频繁）；**菜单键**改为「立即同步」并 toast 结果；底部提示条右侧增加同步状态（`同步中…` / `已更新到 v7` / `离线（使用缓存）`）。标题与宫格数据源改为 repository |
| `ui/WebDisplayActivity.kt` | L81 入口查找、L88 scale 改为从 `ConfigRepository` 快照按 id 取（其余 autoLogin / autoFit / allowInsecureSsl 消费逻辑不变） |
| `tools/build-preview.mjs` + `preview-template.html` | 预览页支持从服务器拉取配置：顶栏显示「配置来源：服务器 vN / 内置兜底」，与 App 的同步行为保持一致；离线仍可打开（用内联兜底配置） |

### 同步触发与节流

- **触发点**：应用启动、`onResume`（回到前台，距上次同步 < 15s 则跳过）、首页菜单键（强制）。
- **`pollIntervalSec > 0`** 时额外启用后台定时轮询（默认关闭）。
- 所有同步都在后台线程；结果通过回调回主线程更新 UI，**绝不阻塞首屏**。

### 需求覆盖对照

| 需求 | 实现 |
| --- | --- |
| 客户端不含增删功能 | 客户端不引入任何写接口，仅消费 `GET /api/config` |
| 内容全部来自服务器 | 入口列表、标题、副标题、URL、图标、主题色、自动登录配置全部服务端下发 |
| 无需重装即可更新 | 服务端改内容 → 客户端启动/回前台/菜单键即生效 |
| 自动检测更新并应用 | 启动即比对 version：无变更得 `304`（极快），有变更自动合并应用 |
| 缓存与弱网体验 | 本地缓存 + 包内兜底；同步失败继续用缓存并显示「离线」状态，不清空已有内容 |
| 启动加载时间 | 首屏用缓存同步渲染（不等待网络），网络同步异步进行 |
| 增量更新 | `since` + `rev` + `tombstones` 增量协议；无变更返回 `304` |
| 版本一致性与控制 | `version` 单调校验 + `epoch` 强制全量；异常自动降级全量重拉 |

## 七、注意事项（写入 README）

1. **无鉴权风险**：任何人都能访问管理后台并修改内容。缓解：服务端部署在内网、用防火墙限制来源网段、必要时只监听指定网卡。
2. **换服务器地址需重新出包**：按选择地址打包内置；如某次运维需要临时切地址，仍可用既有外部文件覆盖能力（`/sdcard/Android/data/com.digitalcenter.tvshow/files/` 下放引导文件），无需重装。
3. **明文 HTTP**：沿用现有 `network_security_config.xml`；如需 HTTPS，入口级 `allowInsecureSsl` 已支持自签名证书。
4. **数据备份**：服务端数据为单个 JSON，定期备份 `server/data/config.json` 即可；服务启动会自动保留 `.bak`。

## 八、验证方法

### 服务端（真实 HTTP 端到端）

1. 启动 `node server/server.js`，`curl` 逐项校验：健康检查、增删改查、标题修改、排序、`since` 增量、**无变更返回 304**、tombstone 删除下发、`epoch` bump 后客户端重拉全量、非法参数返回 400。
2. 用 Playwright 驱动管理后台做端到端操作（改标题 / 新增页面 / 编辑 / 上移下移 / 删除），断言后台界面与 `/api/admin/config` 一致。

### 客户端

3. `./gradlew assembleDebug assembleRelease` + `lintVitalRelease` 通过；`aapt2` 校验 APK 清单。
4. **同步协议逻辑**：用 Node 复刻客户端的合并算法（delta 合并 / version 单调校验 / 异常降级全量 / 缓存回退），对接真实服务端跑用例，覆盖：首次全量、304、增量、删除、乱序 version、epoch 变更、服务端不可用。
5. **预览页镜像验证**：Playwright 打开预览页，验证「服务器 vN / 内置兜底」两种来源、服务器不可用时的降级显示。

> 说明：本环境无 KVM，无法启动 Android 模拟器，**App 侧仍无法做设备端 UI 实机验证**。因此第 3-5 项以编译/静态检查 + 同协议逻辑复刻验证为主，另附一份电视端 adb 验证清单（见下）。
6. **电视端 adb 验证清单**（交付后执行）：装包 → 首屏是否立即出内容 → 服务器改标题 → 电视按菜单键是否更新 → 关服务器再启动是否仍显示缓存内容与「离线」标识 → 断网/恢复的表现。
